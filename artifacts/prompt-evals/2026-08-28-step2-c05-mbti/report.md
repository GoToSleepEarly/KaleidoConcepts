# C05 MBTI 历史提问真实 AI 测试

## 范围

- 历史提问：`用故事讲 MBTI，学生学习到理论`
- 范围：Step 2 需求对齐、必要澄清、背景判断、三个方向、故事大纲；不进入 Step 3–5。
- 模型：5 个互相独立的 Codex 任务，均为 `gpt-5.6-sol / medium`。
- 调用方式：没有使用 API。每次先由项目代码生成生产 Prompt，再把完整 Prompt 交给独立 Codex 任务；原始输出随后回灌当前程序校验。
- 老师决策模拟：第一轮选择 AI 推荐的“理解四组维度”；方向阶段按既定测试规则选择第一张卡。

## 结果

- 实际 AI 调用：5 次；必要澄清 1 次；重试 0 次；格式修复调用 0 次。
- 各调用程序一次通过：5 / 5 = **100%**。
- 端到端程序一次完成：1 / 1 = **100%**。
- 严格输出协议一次命中：3 / 5 = **60%**。首次对齐和背景输出依赖了程序兼容归一。
- 严格业务与内容质量一次完成：0 / 1。阻断原因不是 AI 原始方向，而是程序在方向归一阶段损坏中文；大纲另有明显模板重复，但仍可作为可修改初稿。

## 逐步质量观察

1. 首次对齐正确前置澄清，只问学习深度，给 3 个互斥选项并推荐“理解四组维度”，没有提前搜索。`answerMode=single_select` 与 `resolvedRequirements` 对象不符合协议，但程序没有增加 AI 调用。
2. 回答后对齐正确形成可验证学习目标，但仍把已有课程上下文重复写入 `additionalConstraints.required`，会持续放大后续 Prompt。
3. 背景资料内容准确、适龄，并明确反对刻板印象、优劣排序和永久标签。枚举字段不符合协议，但安全归一后不损失内容。
4. 模型原始三张方向卡差异明显，问题—行动—结果闭合。程序随后把单字姓名“本”替换进普通词“本身”，生成 `错误标签Ben身`；这是一次性质量失败的直接原因。
5. 大纲覆盖 E–I、S–N、T–F、J–P，人物和知识点映射通过；但连续四章均复用“门提出单一要求—两人展示差异—门开启”的模板，违反 Prompt 的相邻章节动作结构不得重复。第三章对 T–F 中价值与人的影响体现偏弱。

## 根因与建议顺序

1. **先修程序姓名归一。** `canonicalizeClassroomNames` 对所有中文姓名执行无边界全文替换；单字姓名必然污染“本身、本次、本章”等普通词。这是跨案例确定性缺陷，应限制为可确认的人名边界，或对单字中文名不做自由文本替换，只依赖 personId / 完整角色字段。
2. **再收紧轻量协议。** 对齐 Prompt 明确 `answerMode` 枚举及 `resolvedRequirements:string[]`，背景 Prompt 已有枚举但模型仍偏离；程序现有兼容安全，不建议为此增加修复调用。
3. **最后处理大纲重复。** 根因不是再加一条“不要重复”，现有 Prompt 已有该规则；所选方向“四扇门对应四维度”本身诱导了四章同构。更有效的是让概念方向卡在设计阶段明确一个贯穿任务，四个维度作为同一因果链中的不同决策依据，而不是四个并列关卡。

所有原始 Prompt、输出、独立任务元数据和程序校验结果保存在本目录各阶段子目录。
