# 课程创建 V2 阶段五：视觉资源

## 模块目标

阶段五负责基于已确认的故事大纲、角色卡和 clean reading 生成课程视觉资源。

本阶段重点复用 V1 Step4 已验证的资源方案、图片状态、失败恢复和成功图片复用机制，同时适配 V2 的角色卡、动态段落数、角色视觉基准、图生图和图片多版本修改。

## 设计原则

- 图片仍统一由 `course_images` 管理。
- 不把图片 URL、prompt、状态写入课程正文。
- 不读取学生版挖空文本或练习题作为图片语义来源。
- 视觉资源读取 clean reading、段落结构、故事大纲、角色卡和人物档案。
- 页面不自动产生图片费用，所有付费生成必须由老师主动触发。
- 成功图片可复用，不重复消耗 AI 成本。
- 失败图片可单张重试。
- prompt 默认不展示给老师，只放在高级信息中。
- 人物档案图和老师上传图只作为外形参考，不作为故事服装、背景、姿势或构图参考。
- 资源方案先生成一份本课统一角色文字设定，再把同一份设定原样注入封面和全部段落插图 Prompt。
- 有外形参考图的画面使用图生图；没有外形参考图的原创角色允许按统一角色文字设定文生图。
- 每次图片生成成功后自动采用；生成失败时保留上一张已采用图片。

## 用户流程

```text
确认角色视觉意图 -> 补齐必要的外形参考 -> 生成含统一角色设定的资源方案 -> 生成封面 -> 生成段落插图 -> 按需展开聊天修改 -> 确认进入预览发布
```

人物外形参考负责身份可辨识度，统一角色文字设定负责故事服装、道具、色彩和绘本风格一致性。Step 5 不再额外生成中间角色造型图。

## 输入边界

必须读取：

- 阶段一授课对象。
- 阶段二故事大纲。
- 阶段二角色卡。
- 阶段四 clean reading。
- 阶段四段落结构。
- 老师和学生人物档案。

不得读取：

- 学生版挖空文本作为图片语义。
- 章节练习题。
- 课后练习题。
- 答案区。

## 图片槽

V2 不再假设每章固定 2 张正文图。

默认图片槽：

- 每课 1 张封面。
- 每个阅读段落 1 张段落插图。
- 需要保持身份的角色可有 1 张当前外形参考图。

不生成：

- 章节练习图片。
- 课后练习图片。
- 答案页图片。

如果后续需要降低成本，可扩展为“每章选择关键段落生成图片”，但 MVP 默认每段一图，保证正文和图片绑定清晰。

## 角色视觉来源

系统不判断“Image 2 是否认识某个人物”。该能力不可验证且会随模型变化，不能作为稳定产品规则。系统只判断已有视觉资产是否足以固定形象，以及老师是否要求还原一个既有人物或角色。

### 人物档案角色

- 老师或学生读取课程人物快照中的 `visualAssetIdSnapshot`，不在页面加载时直接跟随 `Person.activeVisualAssetId` 变化。
- 快照没有人物形象时，该角色显示“需要创建人物形象”，主要角色在补齐前不能生成下游图片。
- Step 5 不复制人物档案的形象创作能力，只提供人物档案编辑入口。
- 人物档案产生新当前形象后，老师必须明确点击“使用最新形象”，课程角色视觉基准才更新；该操作只更新本课程视觉引用并把相关下游图片标记为过期，不重置故事、教学规划或文案练习。

### 原创角色

- 不生成中间角色基准图，资源方案根据故事大纲和角色卡生成本课统一角色文字设定。
- 没有外形参考图时，封面和段落插图按统一角色文字设定直接生成。

### 外部引用角色

外部真实人物、历史人物、公众人物、影视角色、游戏角色和其他已有作品角色统一视为 `referenced`，不再细分“模型可直接生成”。老师必须在两个视觉意图中选择：

- `保持原形象`：必须上传外形参考图；没有参考图时阻断包含该角色的下游图片生成。
- `课堂原创化`：不要求上传，系统根据角色功能和文字描述生成新的课堂形象，不承诺还原原人物或原作角色。

系统默认建议：

- 历史人物、公众人物：推荐“保持原形象”，允许老师主动改为“课堂原创化”。
- IP、影视、游戏角色：默认“保持原形象”。
- 来源无法确认：默认“保持原形象”。

老师主流程只展示会改变下一步操作的三种状态：

- 外形参考已就绪。
- 需要上传参考图。
- 使用文字设定。

结构示意：

```ts
type CharacterVisualIntent = "preserve_identity" | "originalize";

type CharacterVisualSource =
  | "person_asset"
  | "uploaded_reference"
  | "generated_baseline";

type CharacterVisualStrategy = {
  characterId: string;
  intent: CharacterVisualIntent;
  source: CharacterVisualSource | null;
  activeVisualAssetId: string | null;
};
```

## 角色视觉卡

每个需要出现在图片中的角色展示一张视觉卡。

展示：

- 角色名称。
- 来源类型。
- 视觉来源建议。
- 当前外形参考状态。
- 资源方案生成的本课造型文字摘要。
- 上传参考图入口。

状态只保留“外形参考已就绪 / 需要上传参考图 / 使用文字设定”；外形参考上传失败时在卡片内显示错误并允许重试。

不出现在图片中的角色不显示。人物档案角色和选择“保持原形象”的外部角色必须先有外形参考；原创角色和选择“课堂原创化”的外部角色直接使用文字设定。

Step 5 页面只展示故事中需要出现在图片里的角色。未进入故事的课程老师和学生不显示提示卡，也不进入资源方案或图片生成。

## 上传参考图

上传图只用于人物身份外形参考，不进入课程正文。

规则：

- 上传图绑定角色，支持 JPG、PNG、WebP，单文件最大 10 MB。
- 上传后只做格式校验、尺寸归一和持久化，不调用图片生成模型，不产生图片费用。
- 外形参考仅约束脸型、发型、年龄感、体型和可辨识特征；Prompt 必须明确忽略参考图服装、背景、姿势、摄影风格和构图。
- 老师可重新上传外形参考；保存成功后自动成为该角色当前参考，并把引用该角色的下游图片标记为过期。
- 上传失败保留页面输入状态，允许重试。

## 图片生成规则

- 资源方案生成 `visualStyle`、`storyWorld` 和每个角色唯一的 `storyVisualDesign`，代码把同一份英文锁定文本原样注入每个图片 Prompt。
- 有人物档案图或上传外形参考的封面和段落插图读取这些参考并使用图片编辑接口。
- 没有任何外形参考的画面允许按统一角色文字设定使用文生图。
- 对已有封面或段落插图的聊天式修改，同时读取当前图片、该槽位人物外形参考和老师修改要求。
- 业务层向 provider adapter 传递引用图片列表，不绑定供应商的单图或多图参数结构。
- 适配层无论一张还是多张参考图，都先合成为无文字的横版参考板，禁止把竖版人物图直接作为场景画布。
- 所有封面和正文插图持久化为 `1536×864` 的 16:9 PPT 横版画面；不得使用证件照、肖像照或角色立绘构图。

## 资源方案

生成封面和段落插图前，先生成视觉资源方案。

资源方案读取：

- clean reading。
- 每段正文。
- 角色卡。
- 角色视觉策略。
- 可用人物外形参考图。
- 故事大纲。

资源方案输出：

- 封面图槽。
- 每个阅读段落的图片槽。
- 每个图片槽的画面重点。
- 每个图片槽的出场角色。
- 每个图片槽绑定的段落 id。
- 每个图片槽的自包含 image prompt。

资源方案不修改正文、练习、答案或角色卡。

## 段落插图

每个阅读段落默认生成 1 个图片槽。

每个段落图片槽展示：

- 所属章节。
- 段落顺序。
- 段落正文。
- 出场角色。
- 画面重点。
- 图片状态。
- 图片预览。
- 重试入口。

段落插图绑定 `paragraphId`，不绑定题目或学生版挖空文本。

## 封面图

每课生成 1 张封面图。

封面图读取：

- 故事标题。
- 故事大纲。
- 主要角色。
- 人物外形参考图和本课角色文字设定。
- 代表性场景。

封面图是纯画面，不把课程名称、故事标题或文字画进图片。

## 图片生成顺序

推荐顺序：

1. 老师确认角色视觉意图。
2. 为需要保持身份的角色复用人物档案形象或上传外形参考。
3. 生成含本课统一角色文字设定的视觉资源方案。
4. 生成封面图。
5. 生成段落插图。
6. 点击“编辑图片”后对不满意的图片进行聊天式修改。

页面允许单张、单章或全部生成缺失图片。

## 页面行为

页面按一条连续流程组织，不再把新增能力拆成同权重的大模块：

1. 角色确认。
2. 资源方案。
3. 视觉封面。
4. 章节插图。

画面质量是课程级轻量配置，放在流程头部的紧凑工具栏，不单独占用内容卡片。角色确认是第一步，每个角色使用缩略图、状态和必要操作组成紧凑行；人物外形图不使用封面级大预览。

资源方案与图片生成沿用旧版布局和阅读顺序：

1. 三阶段状态：资源方案 -> 视觉封面 -> 章节插图。
2. 独立资源方案摘要：封面数量、章节数量、段落插图数量。
3. 视觉封面使用一张独立的 16:9 大卡片。
4. 章节插图按章节分组，每章显示进度和“生成本章”，段落图片使用双列卡片。
5. 新增的画面质量、人物外形参考和按需聊天修改嵌入旧布局，不改变方案与图片区的信息架构。

主要操作：

- 上传角色参考图。
- 更换外形参考。
- 生成 / 重新生成含本课角色设定的资源方案。
- 生成封面图。
- 生成单张段落图。
- 生成本章缺失图片。
- 生成全部缺失图片。
- 重试失败图片。
- 沿用过期图片。
- 点击“编辑图片”后，基于当前图片输入一句修改要求。
- 查看当前分支的成功版本并采用指定版本。

每个封面或插图槽恢复旧版的 Prompt 查看入口；生成前默认展开便于核对，生成后默认折叠。成功图片始终保留“重新生成”入口。

聊天修改和历史版本属于低频操作：图片成功后只展示紧凑入口，修改框需点击“编辑图片”才出现，历史缩略图需展开“历史版本”才出现，不能长期占用主流程面积。

## 聊天式修改与版本

封面和段落插图使用轻量对话式修改：

- 老师先选中一个成功版本，输入一句修改要求，例如“把背景改成黄昏”或“让人物看向右侧”。
- 每次修改只生成 1 张子版本，记录 `parentAssetId` 和 `userInstruction`。
- 修改失败不改变当前采用版本，不创建成功历史缩略图，并保留本次修改要求供重试。
- 新版本成功后自动成为课程采用版本；生成失败时原采用版本保持不变。
- 老师选择历史成功版本时仍可点击“采用此版本”回退。
- 老师可从任意成功历史版本继续生成新分支；时间线只展示当前选中版本的祖先链，不混入其他分支。
- 更换人物外形参考后，引用该角色的下游图片标记为过期，但不删除已有图片或自动付费重生成。
- 修改输入框默认隐藏，老师点击“编辑图片”后才展开；MVP 不生成长篇 AI 回复，不做多个会话房间或复杂版本对比。

## 画面质量

页面使用一个课程级“画面质量”选择器，应用于之后的新生成、重试和聊天式修改，不追溯改变已有图片。

| 老师界面 | Image 2 `quality` | 说明 |
| --- | --- | --- |
| 中 | `low` | 最低可选生成档位 |
| 高 | `medium` | 默认档位 |
| 极高 | `high` | 最高可选生成档位 |

规则：

- 默认选择“高”，底层请求使用 `quality: "medium"`。
- 页面不展示 `low`、`medium`、`high` 等供应商参数。
- 当前选择保存为课程的后续生成默认值，批量生成使用该值。
- 每个图片版本必须记录实际使用的 `quality`，便于恢复、成本核对和复现。
- 单纯切换质量不会把已有成功图片标记为过期。
- 老师希望用其他质量重做成功图片时，必须创建新版本；原成功版本保留。

## 失败恢复

沿用 V1 图片状态机和恢复原则：

- 远端生成成功但下载或写入失败时，保留远端 URL，重试优先恢复下载，不重复提交生图。
- 页面刷新后根据数据库状态继续显示。
- 单张图片失败不影响其他成功图片。
- 成功且输入未变化的图片直接复用。
- 输入变化导致旧图过期时，不自动重生成。
- 老师可选择沿用旧图或重新生成。

## 下游重置策略

如果阶段四 clean reading 变化：

- 视觉资源标记过期。
- 不自动删除成功图片。
- 老师可选择沿用旧图或重新生成。

如果角色卡、统一角色设定或外形参考变化：

- 引用该角色的封面和段落插图标记过期。

如果只修改练习题，不修改 clean reading：

- 不影响视觉资源。

## API 边界

新系统不使用 `/api/v2` 路径，视觉资源 API 统一位于 `/api/courses/:id/visual-resources/...`。

### `GET /api/courses/:id/visual-resources`

读取课程画面质量、角色视觉卡、资源方案、图片槽、当前采用版本和成功版本历史。GET 不创建付费任务。

### `PATCH /api/courses/:id/visual-resources/settings`

更新之后生成使用的课程画面质量：

```ts
{ quality: "low" | "medium" | "high" }
```

更新设置不改变已有图片状态。

### `PATCH /api/courses/:id/visual-resources/characters/:characterId/intent`

外部引用角色选择“保持原形象”或“课堂原创化”。改变意图后，当前外形参考和引用该角色的下游图片标记为过期，但不删除成功资产。

### `POST /api/courses/:id/visual-resources/characters/:characterId/use-latest-person-visual`

人物档案角色明确采用人物档案最新当前形象。该操作只更新本课程的角色视觉引用并把相关下游图片标记为过期，不修改授课对象基础快照，也不重置故事、教学规划或文案练习。

### `POST /api/courses/:id/visual-resources/characters/:characterId/reference`

上传并保存角色外形参考，请求使用 multipart form data。

行为：

- 校验并归一化上传图。
- 不调用图片模型，直接持久化到 `course_images`。
- 保存成功后自动成为该角色当前外形参考。

### `POST /api/courses/:id/visual-resources/plan/generate`

生成或重新生成视觉资源方案，同时生成全课统一的英文角色视觉设定和自包含图片 Prompt。

### `POST /api/courses/:id/visual-resources/images/generate`

基于统一角色文字设定和当前可用的外形参考生成封面或段落插图。

请求示例：

```ts
{
  scope: "cover" | "slot" | "chapter" | "all";
  slotId?: string;
  chapterId?: string;
}
```

服务端从课程设置读取当前 `quality`；请求不得相信前端传入任意供应商参数。

### `POST /api/courses/:id/visual-resources/assets/:assetId/refine`

基于指定成功版本和一句修改要求生成子版本；服务端同时补齐该槽位需要的人物外形参考。成功后自动采用新版本。

### `POST /api/courses/:id/visual-resources/assets/:assetId/select`

把指定成功版本设为角色或图片槽当前采用版本。选择失败时原采用版本保持不变。

### `POST /api/courses/:id/visual-resources/assets/:assetId/retry`

重试失败生成。存在已生成远端结果时优先恢复下载和持久化，不重复提交生图。

### `POST /api/courses/:id/visual-resources/slots/:slotId/keep`

沿用过期图片。

## 数据结构

图片仍统一进入 `course_images`。为了支持聊天式修改、历史回退和失败恢复，图片槽与不可变图片版本必须分离，不能继续使用“一槽只保存一张当前图片”的结构。

```ts
type CourseImageSlotType =
  | "character_baseline"
  | "visual_cover"
  | "lesson_shot";
```

稳定领域对象：

- `CourseCharacterVisual`
- `CourseVisualResourcePlan`
- `CourseVisualImageSlot`
- `CourseImage`

结构示意：

```ts
type CourseCharacterVisual = {
  id: string;
  courseId: string;
  characterId: string;
  intent: "preserve_identity" | "originalize";
  source: "person_asset" | "uploaded_reference" | "generated_baseline" | null;
  activeAssetId: string | null;
  status: CharacterAssetStatus;
  createdAt: string;
  updatedAt: string;
};

type CourseVisualImageSlot = {
  id: string;
  courseId: string;
  slotType: CourseImageSlotType;
  chapterId?: string;
  paragraphId?: string;
  sourceText: string;
  characterIds: string[];
  focus: string;
  prompt: string;
  activeAssetId: string | null;
};

type CourseImage = {
  id: string;
  courseId: string;
  slotId: string;
  parentAssetId: string | null;
  operation: "initial" | "revision";
  userInstruction: string | null;
  quality: "low" | "medium" | "high";
  sourceHash: string;
  status: "pending" | "submitting" | "generating" | "succeeded" | "failed";
  provider: string;
  providerTaskId: string | null;
  providerImageUrl: string | null;
  storagePath: string | null;
  publicUrl: string | null;
  failureReason: string | null;
  createdAt: string;
  updatedAt: string;
};
```

约束：

- `CourseVisualImageSlot.activeAssetId` 和 `CourseCharacterVisual.activeAssetId` 是“当前采用版本”的唯一引用。
- `course_images` 中的成功版本不可被覆盖或原地改写。
- `parentAssetId` 保存当前修改分支关系。
- 同一付费操作使用 `Idempotency-Key` 防止重复创建版本。
- 质量记录进入生成指纹，但课程设置变化本身不改变已有槽位的内容过期状态。

## 与预览发布的边界

阶段五不生成课件页面，不生成 PDF，不修改正文和练习。

阶段六预览发布读取：

- clean reading。
- 练习结构。
- 视觉资源图片。
- 图片状态。

没有资源方案、封面或段落插图缺失、未采用、生成失败时，仍可使用占位进入预览发布。只有存在生成中任务时，前端禁用“进入预览发布”；后端同时阻断进入预览、直接预览和发布，不能通过 URL 或 API 绕过。

## 验收标准

- 图片仍由 `course_images` 管理。
- 视觉资源不读取学生版挖空文本作为图片语义来源。
- 系统不以“模型是否认识该人物”作为角色视觉判断规则。
- 外部引用角色必须选择“保持原形象”或“课堂原创化”。
- 选择“保持原形象”后，没有上传参考图时不能生成包含该角色的下游图片。
- 选择“课堂原创化”后不要求上传，且界面不承诺还原既有人物或角色。
- 人物档案图和上传图只约束身份外形，故事服装、道具、姿势和构图由本课统一角色设定决定。
- 原创角色不生成中间基准图；没有外形参考的画面按统一角色设定文生图，有参考的画面使用图生图。
- 多角色画面必须携带所有出场角色的当前视觉基准。
- 每个阅读段落默认有一个图片槽。
- 封面图和段落图默认不绘制任何文字。
- prompt 默认不展示给老师。
- 画面质量显示“中 / 高 / 极高”，分别映射 `low / medium / high`，默认“高”。
- 每个图片版本记录实际质量，切换课程质量不使已有图片自动过期。
- 封面和段落插图支持基于成功版本聊天式修改，修改框点击“编辑图片”后才展开。
- 新生成的成功版本自动成为当前采用版本；失败时保留原采用版本，历史成功版本仍可手动回退。
- 修改失败不改变当前采用版本，成功版本可沿任意历史版本继续生成分支。
- 成功图片输入未变化时可复用。
- 输入变化时旧图标记过期，但不自动删除或重生成。
- 图片失败可单张重试。
