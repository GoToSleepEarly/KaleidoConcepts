# 课程创建阶段一：授课对象确认

## 模块目标

阶段一只确认课程管理名称、授课老师、学生和课程时长，并创建一个可恢复的新系统草稿课程。

阶段一不配置故事、英语难度、知识点、题型或视觉风格。保存授课对象本身不产生 AI 费用；人物形象生成仅在用户明确触发时产生费用。

## 路由

- 新建：`/courses/new`
- 已创建课程返回编辑：`/courses/:id/create/audience`
- 保存成功后：`/courses/:id/create/story-outline`

新系统不使用 `/v2` 路由，也不读取 V1 课程。

## 字段

必填：

- 课程名称
- 老师：单选 1 位
- 学生：至少 1 位
- 课程时长：30 / 45 / 60 分钟

不在本阶段收集：

- 英语难度
- 知识点
- 故事主题或参考剧情
- 第三方人物 / IP
- 题型和题量
- 视觉风格

课程名称只用于课程管理。后续故事标题或课件展示标题不得覆盖课程名称。

## 页面结构

- 顶部展示流程位置和课程名称。
- 老师区只展示当前已选老师或“添加老师”。
- 学生区只展示当前已选学生或“添加学生”。
- 课程时长使用单选控件。
- 底部提供取消 / 下一步。

页面不直接铺开全部人物卡片。

## 人物选择

- “添加老师”打开单选弹层。
- “添加学生”打开多选弹层，点击确认后应用选择。
- 支持搜索、最近使用和分页加载。
- 选择器只展示启用人物。
- 已选人物以紧凑卡片展示。

人物卡只展示决策所需信息：

- 当前形象或默认头像
- 中文名 / 英文名
- 年龄 / 性别
- 编辑入口

由于基础资料保存前已经强校验，本阶段不显示“缺英文名、缺年龄、缺外貌”等资料缺失标签。

形象不是下一步的启用条件，课程人物卡不额外展示形象状态文案。

## 就地编辑

- 点击编辑打开居中弹窗，基础资料与人物形象在同一个界面维护。
- 保存后刷新当前选择中的人物展示。
- 人物形象默认提供照片上传，描述生成作为次选入口；详细外貌设置按需展开。
- 图片生成必须由用户明确点击触发，并在操作前显示会产生一次生成。
- 图片生成失败不影响课程表单和人物基础资料。

## 课程人物快照

课程不能长期直接读取会变化的人物档案作为生成真相源。

保存授课对象时，`CoursePerson` 同时保存：

- `personId`
- 课程角色：老师 / 学生
- 中文名快照
- 英文名快照
- 年龄快照
- 性别快照
- 当前人物形象资产 ID 快照，可为空

结果：

- 人物档案后续修改不会暗中改变已创建课程。
- 在授课对象页重新保存时，课程明确刷新为人物档案最新资料。
- 已发布课程始终可追溯当时使用的人物信息和形象版本。

## 初始状态与按钮

初始状态：

- 课程名称为空。
- 未选择老师。
- 未选择学生。
- 未选择时长。
- 下一步禁用。

下一步启用条件：

- 课程名称去除首尾空格后非空。
- 恰好 1 位启用老师。
- 至少 1 位启用学生。
- 时长为 30、45 或 60。

禁用时只展示第一个未完成原因：填写课程名称、添加老师、添加学生或选择时长。

## API 合同

### `POST /api/courses`

原子创建课程和人物快照。

请求必须携带 `Idempotency-Key`。同一账号和相同 key 重试时返回第一次创建的课程，不重复创建草稿。

```ts
type CourseAudienceInput = {
  title: string;
  teacherId: string;
  studentIds: string[];
  durationMinutes: 30 | 45 | 60;
};
```

响应：

```ts
{
  course: {
    id: string;
    lifecycleStatus: "draft";
    currentStage: "story_outline";
  };
}
```

失败：

- `400` 课程信息不完整。
- `404` 人物不存在。
- `409` 人物不可用或角色不匹配。
- `500` 课程创建失败。

创建失败时不留下半完成课程，前端保留全部表单内容。

### `GET /api/courses/:id/audience`

读取课程管理名称、时长、课程人物快照及当前人物档案摘要。

历史快照和当前档案有变化时，响应返回 `profileChanged = true`，但不自动覆盖课程快照。

### `PUT /api/courses/:id/audience`

更新授课对象并刷新人物快照。请求同 `CourseAudienceInput`。

如果故事大纲尚不存在，直接在事务中更新。

如果已存在下游内容：

- 只修改课程名称：直接保存，不影响下游。
- 修改老师、学生或时长：返回 `409`，要求确认重置。
- 请求带 `resetDownstream = true` 后，在单个事务中更新授课对象、刷新快照、重置故事大纲 / 教学规划 / 文案练习，并把相关成功图片标记为过期。
- 不物理删除已成功图片。

事务失败时课程和全部下游内容保持原状。

## 数据结构

新系统不需要 `workflowMode`。

```ts
type Course = {
  id: string;
  title: string;
  durationMinutes: 30 | 45 | 60;
  lifecycleStatus: "draft" | "published" | "archived";
  currentStage:
    | "audience"
    | "story_outline"
    | "teaching_plan"
    | "content"
    | "visual_resources"
    | "preview";
  createdAt: Date;
  updatedAt: Date;
};

type CoursePerson = {
  id: string;
  courseId: string;
  personId: string;
  role: "teacher" | "student";
  chineseNameSnapshot: string;
  englishNameSnapshot: string;
  ageSnapshot: number;
  genderSnapshot: "male" | "female";
  visualAssetIdSnapshot: string | null;
  createdAt: Date;
  updatedAt: Date;
};
```

约束：

- 一个课程恰好一个老师关联。
- 一个课程至少一个学生关联。
- 同一人物不能在同一课程中重复关联。
- 英语难度和知识点不进入 `Course`，由后续教学规划作为唯一真相源。

## 状态与失败恢复

- 新建页未提交前不创建数据库记录。
- 创建成功后 `currentStage = story_outline`。
- 更新失败不创建新课程，不改变旧快照。
- 人物编辑失败时抽屉保留输入，课程选择保持原状。
- 人物形象生成失败不影响基础资料或课程保存。
- 修改关键授课对象导致的下游重置必须由用户二次确认并原子执行。
- 页面重复提交使用 `Idempotency-Key` 幂等保护，避免创建两门相同草稿课程。

## 验收标准

- `/courses/new` 直接进入可填写的授课对象页面。
- 阶段一只出现课程名称、老师、学生和课程时长。
- 人物通过搜索弹层选择，不铺开全部人物。
- 基础资料完整，因此不显示资料缺失标签。
- 无形象不阻断下一步，但显示一致性收益提示。
- 可以在当前页面通过同一个编辑弹窗维护人物资料和人物形象。
- 保存课程时写入人物快照。
- 人物档案后续变化不自动改变已有课程。
- 修改名称不重置下游；修改老师、学生或时长需要确认并原子重置下游。
- 阶段一保存不自动产生 AI 费用。
- 新系统代码、API 和数据不含 V1 兼容分支或 `V2` 后缀。
