# 课程创建 V2 阶段二：故事大纲

## 模块目标

阶段二负责把老师的自然语言想法生成可确认、可编辑、可追溯的结构化故事大纲。

本阶段只确认故事和人物，不配置英语难度、知识点、题型、章节练习、课后练习或图片 prompt。

确认故事大纲后，进入阶段三“教学规划”。

## 设计原则

- 老师只需要输入自然语言想法，不需要理解人物、IP、故事设定等平台分类。
- AI 返回内容必须渲染成可交互组件，不展示原始长文本、JSON、Markdown 或 prompt。
- MVP 不做复杂局部重生成，只支持编辑整份大纲和全局重新生成。
- 本期不做严格商业化或版权限制，故事是否适合课堂由老师判断。
- 如涉及真实人物、IP、游戏角色或敏感内容，只做轻量提示和课堂化改编，不直接阻断生成。

## 用户流程

```text
输入想法 -> AI 识别背景信息 -> 必要时检索 -> 生成结构化故事大纲 -> 老师编辑或对话调整 -> 确认进入教学规划
```

老师如果想优化大纲，直接在对话框继续发送自然语言要求。系统根据当前大纲和新要求重新生成整份结构化大纲。

示例：

- 更贴近贝多芬真实成长经历
- 不要战斗，改成合作解谜
- 让 ZiXuan 多参与
- 把场景从海底改成太空学校

## 老师输入区

输入区只保留两个入口：

- 我有想法
- 帮我生成

### 我有想法

老师输入任意自然语言，可以混合包含：

- 真实人物，例如特朗普、马斯克、贝多芬
- 虚拟角色或 IP，例如小马宝莉、瓦罗兰特 Jett
- 原创故事设定，例如学生变成美人鱼
- 参考剧情
- 学生参与要求
- 不想出现的内容

系统自动识别输入类型，不要求老师选择“真实人物 / 虚拟角色 / 故事设定”等细分类。

### 帮我生成

老师没有明确想法时使用。

输入框可选。系统根据阶段一的老师、学生和课程时长生成 3 个故事方向卡。

老师选择一个方向后，系统再生成完整结构化故事大纲。

## 生成数量规则

- 老师输入明确时：生成 1 个主故事大纲。
- 老师输入模糊或选择“帮我生成”时：先生成 3 个故事方向卡，不生成 3 个完整大纲。
- 老师选定方向后：生成 1 个完整故事大纲。

不保留 V1 “一次生成 3 个完整大纲让老师阅读比较”的模式。

## 章节数量

章节数量在生成故事大纲前确定。

默认值按课程时长给出：

- 30 分钟：3 章
- 45 分钟：4 章
- 60 分钟：5 章

老师可以在生成前修改章节数。

故事大纲生成后章节数锁定，不允许直接修改。如果要修改章节数，需要重新生成故事大纲。

章节数会影响故事结构、教学规划、题量、图片数量和预览页数，因此不能在生成后轻量改动。

## AI 内部流程

用户侧只看到一次生成动作；系统内部至少分两步：

1. 意图解析 / 背景识别
2. 故事大纲生成

如识别到真实人物、历史人物、IP、游戏角色、影视角色或公共事件，系统可进行联网检索或资料确认。

解析结果包括：

- 输入中有哪些人物、角色、作品或事件
- 哪些需要检索
- 哪些是原创设定
- 是否存在歧义
- 是否包含明显不适合儿童课堂的内容
- 建议的故事类型

如果 AI 不确定对象，不硬编。MVP 可展示候选对象让老师选择，或提示老师补充信息后重新生成。

## 引用对象处理

引用对象包括真实人物、历史人物、公共人物、IP、游戏角色、影视角色等。

处理规则：

- 不因为真实人物、IP 或角色直接阻断生成。
- 允许课堂化改编。
- 涉及明显成人、暴力、政治争议内容时，只给短标签提示。
- 检索失败时允许继续，但引用对象记录为来源未确认。
- 本期不做复杂版权、商业化使用或合规审核。

## 角色卡

角色卡由 AI 在故事大纲生成过程中自动抽取，不要求老师提前手动创建。

角色来源分三类：

1. 课程人物
   - 来自阶段一选择的老师和学生。
   - 关联 `Person.id`。
   - 后续视觉资源阶段可读取人物档案和视觉资产。

2. 引用角色
   - 来自老师输入和背景识别，例如特朗普、贝多芬、小马宝莉、Jett。
   - 关联来源参考记录。
   - 保存来源摘要、身份描述和视觉关键词。

3. 原创角色
   - AI 为故事需要新增的角色，例如海底图书管理员、时间机器人。
   - 保存名字、故事功能和基础外貌描述。

角色卡是后续人物一致性和图片生成的语义真相源起点。本阶段不生成图片，不生成最终视觉资产。

每个角色至少包含：

```ts
type CourseCharacter = {
  id: string;
  courseId: string;
  displayName: string;
  sourceType: "person" | "referenced" | "original";
  sourcePersonId?: string;
  sourceReferenceId?: string;
  roleInStory: string;
  shortDescription: string;
  visualDescription?: string;
  shouldAppearInImages: boolean;
};
```

## 故事大纲组件

AI 返回严格结构化数据，前端渲染为组件。

页面组件包括：

- 故事标题卡
- 故事一句话概括
- 引用对象卡
- 角色卡片组
- 章节大纲卡片组

### 故事标题卡

展示：

- 故事标题
- 一句话概括

支持编辑。

### 引用对象卡

仅在识别到引用对象时展示。

展示：

- 引用对象名称
- 类型：真实人物 / 历史人物 / IP / 游戏角色 / 其他
- 来源摘要
- 改编边界
- 来源状态

支持编辑补充。

### 角色卡片组

展示故事中会出现的人物和角色。

支持编辑角色描述。

### 章节大纲卡片组

每章一张卡。

每章展示：

- 章节标题
- 剧情目标
- 关键事件
- 出场角色
- 场景
- 结尾推进点

支持编辑。

## 编辑和重生成

MVP 只支持：

- 编辑结构化大纲组件
- 全局重新生成故事大纲

不支持：

- 单章重生成
- 单角色重生成
- 单卡片重生成
- 复杂版本历史
- 多版本对比

编辑不是编辑原始文本，而是编辑结构化组件字段。

全局重新生成会基于：

- 阶段一授课对象
- 当前老师输入
- 当前对话补充要求
- 当前章节数
- 背景识别和检索结果

重新生成后替换整份故事大纲。

## 与教学规划的边界

故事大纲阶段不配置：

- 英语难度
- 全局知识点
- 每章知识点
- 题型
- 题量
- 章节练习
- 课后练习
- 图片 prompt
- 最终视觉风格

这些进入阶段三“教学规划”或后续“视觉资源”阶段。

## 确认进入下一步

进入教学规划前需要满足：

- 故事标题存在。
- 至少存在一个主角或课程人物参与故事。
- 章节数量已锁定。
- 每章有标题、剧情目标和关键事件。
- 角色卡已生成。

如存在来源未确认的引用对象，MVP 不阻断进入下一步，由老师自行判断是否继续。

## 下游重置策略

如果故事大纲已经确认并进入后续步骤，老师返回修改故事大纲并保存时，必须弹确认：

```text
修改故事大纲会重置后续教学规划、文案与练习、视觉资源，是否继续？
```

确认后：

- 重置教学规划。
- 重置文案与练习。
- 重置视觉资源。
- 保留阶段一授课对象。
- 保存新的故事大纲。

取消后：

- 不保存故事大纲修改。
- 不影响后续内容。

## API 边界

V2 API 使用 `/api/v2/...`。

### `GET /api/v2/courses/:id/story-outline`

读取当前故事大纲、对话输入、章节数和生成状态。

响应：

```ts
{
  outline: CourseStoryOutline | null;
  chapterCount: number;
  generation: {
    status: "idle" | "running" | "succeeded" | "failed";
    error: string | null;
  };
}
```

### `PUT /api/v2/courses/:id/story-outline/settings`

在生成故事大纲前保存章节数等生成设置。

请求：

```ts
{
  chapterCount: number;
}
```

行为：

- 只允许在故事大纲生成前修改章节数。
- 如果已有故事大纲，返回 409。

### `POST /api/v2/courses/:id/story-outline/generate`

生成或全局重新生成故事大纲。

请求：

```ts
{
  mode: "idea" | "random";
  message?: string;
}
```

行为：

- `mode = "idea"` 时 `message` 必填。
- `mode = "random"` 时 `message` 可选。
- 明确输入时生成 1 个完整故事大纲。
- 模糊或随机输入时可先返回 3 个方向卡。
- 生成成功后保存结构化故事大纲和角色卡。

### `PUT /api/v2/courses/:id/story-outline`

保存老师编辑后的结构化故事大纲。

行为：

- 校验结构完整性。
- 若后续步骤已存在，需要请求中带确认标记才允许保存并重置下游。

请求：

```ts
{
  outline: CourseStoryOutline;
  resetDownstream?: boolean;
}
```

## 数据结构

建议新增稳定领域表，不使用 V2 后缀：

- `CourseStoryOutline`
- `CourseSourceReference`
- `CourseCharacter`

草稿结构示意：

```ts
type CourseStoryOutline = {
  id: string;
  courseId: string;
  chapterCount: number;
  title: string;
  summary: string;
  sourceReferences: CourseSourceReference[];
  characters: CourseCharacter[];
  chapters: CourseStoryOutlineChapter[];
  createdAt: string;
  updatedAt: string;
};

type CourseSourceReference = {
  id: string;
  courseId: string;
  name: string;
  type: "real_person" | "historical_person" | "ip" | "game_character" | "fictional_character" | "other";
  sourceStatus: "confirmed" | "unconfirmed";
  summary: string;
  adaptationBoundary: string;
};

type CourseStoryOutlineChapter = {
  id: string;
  order: number;
  title: string;
  storyGoal: string;
  keyEvents: string[];
  characterIds: string[];
  setting: string;
  endingHook: string;
};
```

## 失败恢复

- 生成失败：保留老师输入和已有故事大纲，允许重试。
- 检索失败：允许继续生成，但引用对象标记为来源未确认。
- 保存失败：不覆盖原故事大纲，保留当前编辑内容后重试。
- 修改已确认故事大纲：必须二次确认是否重置下游步骤。

## 验收标准

- 老师可以通过一个自然语言输入框表达人物、角色、IP、故事设定和参考剧情。
- 页面只提供“我有想法”和“帮我生成”两个入口。
- 明确输入时生成 1 个完整故事大纲。
- 无想法时先生成 3 个故事方向卡，选择后再生成完整大纲。
- AI 输出渲染为结构化组件，不展示原始长文本。
- 章节数生成前可修改，生成后锁定。
- 支持编辑结构化故事大纲。
- 支持全局重新生成故事大纲。
- 不支持局部重生成。
- 角色卡自动生成，并能作为后续视觉资源的角色真相源起点。
- 修改已确认故事大纲时，必须确认是否重置后续步骤。
- 本阶段不出现英语难度、知识点、题型、题量、章节练习、课后练习和图片 prompt 配置。
