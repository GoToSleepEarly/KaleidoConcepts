# 课程创建阶段四：文案与练习

## 文档状态

- Grammar in Use 来源上下文、统一知识点 ID 和 0 知识点章节行为：已实现，待用户验收。
- 状态：核心契约与 2026-08-15 补充规则均已实现，待用户验收。
- 本文档替代此前“先生成无题正文，再向正文插题”的 Step 4 草稿。

## 模块目标

Step 4 基于已确认的故事大纲和教学规划，生成可直接渲染的英文课程内容：

- 各章完整英文正文。
- 与正文联合生成的语法题和词汇题锚点。
- 每章章节语法练习。
- 全课 `Main Idea Reading Practice`。
- 课后语法练习。
- 由程序自动生成的课后词汇匹配。

本阶段采用显式两阶段流程：

```text
生成结构化正文 + 正文内嵌题 + Main Idea
-> 老师检查最终正文呈现
-> 生成章节练习 + 课后语法练习
-> 程序汇总生成课后词汇匹配
-> 老师确认全部内容
```

第一阶段已经包含正文题。不能先自由生成正文，再寻找位置硬插题；否则无法稳定保证题量、知识点覆盖和安全挖空。

## 核心原则

- 一章只保存一份可拼回答案的结构化正文。
- 完整阅读和边读边练是同一份正文的两种编译结果，不生成两套英文。
- clean text 由顺序 parts 拼接得到，是章节练习、Main Idea 和视觉资源的语义真相源。
- AI 不输出 HTML、Markdown 排版、题号、横线、字符位置或图片 prompt。
- 后端负责 ID、分页、选项顺序、横线、提示、答案区和最终组件结构。
- 语法知识点只约束语法题；词汇题不绑定语法知识点。
- 正文语法题、章节语法练习和课后语法练习分别独立覆盖各自配置的全部语法知识点。
- 生成和校验结果持久化，刷新或离开页面不能重复产生 AI 费用。
- 图片 URL、prompt 和图片状态继续只由 `course_images` 管理，不写入正文结构。
- Grammar in Use 来源只增强 AI 对知识点的理解，不改变已有生成、校验和最小修复框架。目录与展示边界统一遵循 `docs/frontend/grammar-knowledge-library.md`。

## 输入与真相源

Step 4 只读取已确认的上游状态：

- Step 1：授课老师、学生快照、课程英语难度和所选 Grammar in Use 书籍版本。遗留课程时长不进入正文篇幅或 Prompt。
- Step 2：故事主线、角色、章节顺序、标题、摘要和知识点推荐基线。
- Step 3：老师最终确认的每章词数、语法知识点、正文模式、正文题量、章节练习配置和课后练习配置。

Step 4 不重新使用 Step 2 推荐推导知识点，不允许 AI 新增语法知识点，也不允许在本阶段修改题型、题量、难度或知识点配置。

只有 Step 3 实际分配到章节或课后语法练习的知识点进入对应生成与覆盖校验。0 知识点章节仍生成 clean text、词汇题和阅读内容，但不生成正文语法题或章节语法练习；正文自然出现的其他语法结构不形成考查知识点。

## 题型边界

领域层不得继续使用一个通用 `ExerciseType` 表达所有场景。

```ts
type GrammarExerciseType = "option_cloze" | "word_form";
type ReadingVocabularyType = "chinese_hint";
type HomeworkVocabularyType = "matching";
```

使用范围：

- 正文语法题：选项填空、给词变形。
- 正文词汇题：中文提示写词或词组。
- 章节练习：只允许语法选项填空和给词变形。
- 课后练习：语法选项填空、给词变形，以及程序生成的中英匹配。

语法题必须绑定一个且仅一个统一 `KnowledgePoint.id`。一个语法知识点可以由多道题考查；每组练习先完整覆盖全部知识点，额外题量由 AI 根据题型适配度分配，不要求机械平均。来源 Unit 不产生额外题目或覆盖要求。

词汇题只绑定正文派生的词汇项，不绑定 `knowledgePointId`，也不计入语法知识点覆盖数量。

## 页面结构

本模块同时遵循 `docs/frontend/course-ai-workspace-ui-guidelines.md`。

页面使用左右布局。左侧沿用 Step 2 的聊天工作区，不再拆成“生成助手”和“生成流程”两张配置卡：

- 页面主标题固定为当前模块“文案与练习”，使用与其他创建步骤一致的标题字号；Step 2 已确认的故事题目紧随其下作为辅助信息，课程名称只保留在课程层级。

- 左侧顶部：Step 4 独立模型选择。
- 左侧时间线：助手引导语、开始生成按钮、真实生成阶段、检查与修复消息，以及正文完成后的下一步按钮。
- 左侧底部：单行起步、随内容增长的聊天输入区，以及与范围选择同行的可清除修改目标。

右侧不是 JSON、Markdown 或编辑器；所有内容必须渲染为课程组件。

右侧使用“一级内容 Tab + 章节二级 Tab + 单页预览”，替代常驻目录、下拉选择器和纵向内容长列表。内容页是右侧的视觉重心。

- 选择 Chapter 后，二级 Tab 显示“正文”和存在时的“练习”；该章没有章节练习时不显示“练习”。Reading 和课后练习也使用同高、同内边距、同激活线的二级导航项，不能退化为未对齐的普通文字。
- `Reading` 对应 Main Idea Reading，不显示无意义的二级 Tab。
- 没有课后练习时不显示一级“课后练习”Tab；选择课后练习后，词汇匹配和语法练习作为连续页面，不再增加第三级导航。
- 初次进入且尚无正文成果时只显示居中的创作聊天框，不渲染空预览框；产生正文页后再切换为聊天区与预览区双栏。

- 初始状态按内容自然高度展示，不使用固定最小高度制造空腔，也不展示尚不可用的修改输入框。开始生成后在原位置切换为任务 Loading；生成进度卡保持普通助手消息宽度，不横向拉成长条。
- 顶部课程步骤条属于已确认设计，本轮聊天布局优化不得修改其结构、尺寸、配色或交互。
- 默认打开第 1 章正文；后台状态变化不能强制切走老师当前查看位置。
- 每次只渲染一张最终内容页，一级 / 二级 Tab 负责切换内容区域；上一页、页码、下一页和修改当前页合并到二级导航右侧的同一局部工具栏，到达边界后置灰，不再让翻页控件单独占据画布下方一行。

- 预览翻页使用明确的上一页、下一页按钮。焦点轮廓只展示在真实可交互控件上，不让整个预览窗口成为额外焦点或出现四边窗口轮廓。

- 首次进入时，助手用简短引导语说明将先生成全部章节正文、正文题和课后阅读，并提供主按钮“生成正文与课后阅读”。
- 老师必须主动点击开始，不因进入页面或输入框内容自动产生 AI 请求。
- 正文未开始时不展示不可用的修改输入框。

- 已有生成结果或真实历史消息后，不再常驻显示首次进入时的固定助手引导，避免把重复说明挤入对话历史。

- 老师发送修改、系统进入处理中或生成与修改结果返回后，左侧聊天时间线自动定位到底部，确保最新反馈和后续操作可见。

## 分页规则

正文页数直接使用 Step 3 已确认的每章 `paragraphCount`：

- 一个正文段落对应一个正文内容页。
- AI 必须生成与 `paragraphCount` 完全相同的段落数量。
- 各段情节要完整，题目随自然语境落入段落。服务端只硬校验段落数量、整章各题型总量和知识点覆盖，不校验每段题量或每段题型分布。
- Step 4 不根据词数或题量重新推导段落数。
- 正文段落数不参与章节练习或课后练习分页；两类练习只按各自题量分页。

章节练习和课后练习：

- 同一题型单页容量为 5 题；超过 5 题时按最少页数均衡分配，词汇匹配遵循相同规则。
- 例如 6 题分为 3+3，9 题分为 5+4，11 题分为 4+4+3；题目顺序保持不变。
- 同一题型跨页时题号连续。
- 词汇匹配必须页内闭包：每个英文项对应的中文项必须在同一页。
- 词汇匹配只在页内打乱，不能全局打乱后再分页。

## 第一阶段：结构化正文与正文题

老师点击 `生成正文内容` 后，系统生成：

- 各章结构化正文与正文题。
- 各章 clean text。
- 全课 Main Idea Reading Practice。

### 联合生成方式

AI 返回顺序 parts，不返回完整文本加字符位置。

```ts
type GeneratedSentencePart =
  | {
      type: "text";
      text: string;
    }
  | {
      type: "grammar";
      exerciseType: "optionCloze";
      knowledgePointKey: string;
      answer: string;
      distractors: [string, string];
    }
  | {
      type: "grammar";
      exerciseType: "wordForm";
      knowledgePointKey: string;
      answer: string;
      baseForm: string;
    }
  | {
      type: "vocabulary";
      answer: string;
      canonicalForm: string;
      meaningZh: string;
    };

type GeneratedParagraph = {
  parts: GeneratedSentencePart[];
};

type GeneratedChapter = {
  outlineChapterId: string;
  paragraphs: GeneratedParagraph[];
};

type GeneratedReadingBundle = {
  chapters: GeneratedChapter[];
  mainIdea: { text: string };
};
```

故事标题、章节标题和课后阅读标题均为上游或产品固定值，不要求 AI 复述。服务端固定使用章节大纲标题和 `Main Idea Reading Practice`，解析层兼容并丢弃旧模型可能额外返回的 `title`。

clean text 只能由 parts 派生：

```ts
const cleanParagraph = parts
  .map((part) => part.type === "text" ? part.text : part.answer)
  .join("");
```

约束：

- 不让 AI 返回字符偏移。
- 不同时让 AI 返回另一份 `sentence.text`。
- `knowledgePointKey` 使用 Prompt 内稳定短键 `KP1`、`KP2`，后端映射为真实 ID。
- 每个短键的可读上下文包含系统知识点标题、书名、版本、官方书籍等级，以及全部来源 Unit 编号和准确官方标题；课程英语难度作为独立字段传递，不与书籍等级合并。
- 后端生成章节、段落和练习真实 ID。
- 一个 exercise part 天然占据一个顺序位置，同一字符范围不能绑定两道题。
- 同一句可以出现多道题，但语法与词汇题锚点不能重叠。
- 首次生成和局部修复复用同一个章节 Schema。
- 正文 Prompt 的优先级固定为：上游故事事实与状态连续性 > 英语自然度与 CEFR 可读性 > 题目自然嵌入 > JSON 结构。不得为了安放题目改变人物目标、关键因果、物品去向或章节结果。
- CEFR 只控制英文的词汇范围、句长、语法结构、连接方式和描写深度，不得改变、删减或重排上游核心事件。Step 4 使用按 Starter、A1、A2、B1、B2、C1、C2 明确区分的共享写作档案；首次正文、正文修复、课后阅读修复、练习生成与修复、老师局部修改必须复用同一档案。
- 低等级不得以电报式短句或省略因果来伪装简单。应减少非必要修饰、隐喻和心理描写，使用明确主语及 `and`、`but`、`because`、`so`、`then` 等适龄连接方式完整表达行动、原因和结果。
- Step 4 读取全篇故事总述和正式角色的剧情作用。课堂人物使用人物快照中的英文名；其他角色在英文正文中使用一致的通行英文名或自然罗马字写法。
- 每个段落承担一个清楚的剧情推进，前一段结果必须为下一段行动提供原因；不设置额外句数或逐段题量限制。整章各题型总量必须符合教学规划，具体题目随自然语境分布。
- 正文整体语法、叙事时态和故事时间线的正确性高于知识点植入与题量覆盖。每章必须先确定叙事基准时态；其他时态只能在时间提示、事件先后或对话语境明确支持时使用。知识点无法自然嵌入时应改写局部语境，不得只替换动词形式造成上下文冲突。
- AI 输出前必须按顺序拼接完整 clean text，检查主谓一致、代词指代、单复数、时态与体、语序和前后逻辑，再返回结构化 parts。
- Step 4 只在 Step 3 最终知识点与 Step 2 推荐组合完全一致时接收该章精简的知识点使用语境；老师增删知识点后不传过期推荐说明，由 Step 4 根据最终知识点和章节剧情重新规划。该可选文本不新增字段或 AI 调用。
- 正文生成顺序固定为：先在内部形成语法和逻辑正确的 clean text，再从自然存在的结构中设置题目锚点。不得先指定知识点答案或词形，再倒推、拼接正文句子。
- 0 知识点章节的 Prompt 不分配语法短键和语法槽位，只保留故事、CEFR、篇幅、段落和词汇题约束；不得为了维持旧默认题量临时新增知识点。
- 词数按完整 clean text 计算，所有题目锚点的 `answer` 都计入。偏少会影响教学内容完整度，因此继续严格修复；偏多主要影响篇幅，允许比目标多 30 词，避免为少量超出再次调用 AI。例如目标 120 词时，硬验收为 106-150，首次生成瞄准 110-120；超预算时压缩非必要修饰、重复动作、心理描写和过渡句，不删减核心事件与因果。
- 失败章节修复还会提供当前实际词数、最低净增减词数和推荐净增减区间。修复必须进入安全区间，不能只让结果比上一版更接近目标。
- AI 输出 Schema 按题型区分必填字段：选项填空必须提供两个 `distractors`，给词变形必须提供 `baseForm`，不使用跨题型的可选字段。
- 首次生成、失败目标修复和老师主动修改均携带与当前目标相关的最小正确 JSON 示例；正文示例覆盖选项填空、给词变形和词汇词组，独立练习示例同时明确 `before`、`after` 与填空提示的位置。
- 程序可将旧格式中“两个干扰项”或“答案加两个干扰项”的 `options` 确定性转换为 `distractors`；只有无法安全转换时才进入 AI 格式修复，避免为机械转换重复付费。
- 练习解析采用“宽进严出”：程序可确定性处理无害的外层说明文字、旧外层字段名、`exerciseType`、`options`、`baseWord`、答案混入三个干扰项以及额外元数据，最终仍只保留标准 Schema。无法推导的题干、答案或知识点不得猜测，才进入 AI 格式修复。
- 正文 `parts` 中值为 `""` 的 `text` 片段不承载任何语义，解析时由程序直接删除；只包含必要空格的连接片段继续保留。该规则不得放宽答案、知识点短键、词汇原形、中文释义或 Main Idea 的非空校验，也不得为删除空片段调用 AI 格式修复。
- 每次生成最多执行一次 AI 格式修复。格式修复只允许删除多余字段或机械转换已有字段；缺少正文、题干、答案或知识点等语义内容时不得编造，也不进行第二次同类付费修复。
- 文本 provider 保留每次响应的 `inputTokens`、`outputTokens`、`reasoningTokens`、扣除推理后的 `visibleOutputTokens` 和 `totalTokens`，开发日志按 operation 单独记录，便于区分首次生成、格式修复、业务修复和老师主动修改的费用。
- 开发环境必须记录每轮 Schema 解析失败的具体 Zod 路径和原因，不能只记录最终“结构解析失败”。
- 失败章节进入 AI 修复前，程序必须把持久化结构反向转换为干净的生成契约：移除内部 ID、校验信息和打乱后的 `options`，把真实知识点 ID 还原为 Prompt 短键，并恢复 `distractors`。不得把数据库结构与目标输出 Schema 同时交给 AI。
- 老师主动修改正文页、整章正文、章节练习页或课后练习页时同样先执行上述转换。单段修改只传当前段落以及前后相邻段落，不再把包含目标段落的整章正文重复传入。

### 正文题渲染

完整阅读模式：

- 显示拼回答案后的完整英文。
- 语法锚点和词汇锚点都高亮，并使用两种样式区分。
- 词汇锚点在高亮英文后紧跟存储的中文释义，如 `current（水流）`；语法锚点不追加释义。
- 只提供简短图例，不显示正文题号或额外正文答案区。

边读边练模式：

- 语法选项填空：`Summer ______ (found / lost / painted) the glowing map.`
- 给词变形：`Yesterday, Mia ______ (find) the hidden door.`
- 中文提示写词：`The map showed a secret _____ (路线，5个字母).`
- 中文提示写词组：`Mia ______ _____ (照顾，6+5个字母) the fox.`
- 提示始终紧跟在答案所在空格后面，不能统一放在句末。
- 正文内不显示题号。
- 每页下方按阅读顺序显示教师答案，例如：`本页答案：found · looked after · route`。

词汇横线和字母数由程序根据正文实际答案生成，AI 不返回横线或 `6+5`：

- 每个空格分隔的英文单词对应一条独立横线。
- 字母数按正文实际 `answer` 计算，不按 `canonicalForm` 计算。
- MVP 不选择带连字符或缩写符号的词作为正文目标词汇。

所有选项填空统一为 3 个无编号选项。AI 返回正确答案和两个干扰项，程序检查不重复后确定性打乱并持久化顺序。正文、章节练习和课后练习复用同一选项填空结构和渲染组件。

干扰项必须与答案考查相同词性或语法维度，在当前句子中具有合理迷惑性，但完整句子只能有一个正确答案。词汇题优先选择可复用的实词或常用词组，不选择人物名、地名、纯功能词、缩写、带连字符词或重复的 `canonicalForm`。

### 词汇池

AI 不额外返回 `targetVocabulary` 数组。正文词汇题本身是唯一词汇来源：

- `answer`：正文中的实际词形或词组。
- `canonicalForm`：词典原形，用于去重。
- `meaningZh`：当前正文语义下的中文含义。

程序从全部 `vocabulary_chinese_hint` parts 提取词汇项，并按 `canonicalForm + meaningZh` 去重。该结果用于课后中英匹配，不再调用 AI。

### Main Idea Reading Practice

- 全课只有一篇。
- 中文产品名固定为“课后阅读”，英文名固定为“Main Idea Reading Practice”。
- 与全部章节正文在首次 Prompt 中一起生成，并通过同一个响应 Schema 返回。
- 目标词数读取 Step 3 的 `mainIdeaTargetWordCount`，默认 120 词；优先范围为目标值上下 5 词，验收范围为目标值上下 10 词，并共同限制在 80-150 词内。
- 概括主要人物、问题、关键发展和结果，不与正文事实冲突。
- 纯阅读，不高亮、不挖空、不带题目。
- 不承担语法知识点覆盖，也不进入正文词汇池。
- 本阶段不生成任何图片；Main Idea 是否在后续视觉资源阶段配图，由视觉资源模块另行确认。
- 页面位置在全部章节之后、课后练习之前。

## 第二阶段：章节与课后练习

老师检查第一阶段结果后，点击 `确认正文，生成练习`。

### 章节练习

- 只生成 Step 3 开启的章节练习。
- 只包含语法选项填空和给词变形。
- 以本章人物、事件、场景和事实为素材。
- 重新编写题目句子，不直接复制课文原句。
- 不得创造与课文冲突的情节或事实。
- 每章章节练习独立覆盖本章全部语法知识点。
- 题量多于知识点时，由 AI 按题型适配度分配额外题目。

### 课后练习

Step 3 选择不生成课后练习时，本节不存在。

生成时包含两个独立部分：

1. 课后语法练习：基于 CEFR 难度和课后所选语法知识点生成，不依赖课文情节；独立覆盖全部课后语法知识点。
2. 课后词汇匹配：程序汇总各章正文词汇题、按 `canonicalForm + meaningZh` 去重并分页，不调用 AI。

词汇匹配每页最多 5 组，超过时均衡分配；英文项和中文项只在本页内打乱，每页保存独立且稳定的答案映射。

## 教师修改

MVP 右侧只读渲染，不开放正文整段自由编辑，避免破坏 exercise parts、答案和知识点覆盖。

老师通过左侧聊天框修改。修改范围由界面和程序确定，不让 AI 猜：

- 输入区上方提供紧凑的修改范围选择器；未选择范围时可以输入，但发送按钮禁用。
- 老师可明确选择某章正文页、Main Idea、某个章节练习分页或某个课后语法分页。
- 每个可修改的右侧内容页在悬停或键盘聚焦时显示“修改本页”。点击只选择目标、突出当前页并聚焦输入框，不立即调用 AI。
- 选中目标以可清除标签展示，例如“第 2 章 · 章节练习 · 选项填空第 1 页 ×”。点击 `×` 只清空目标并保留已输入文字；“全部清空”同时清除目标和文字。
- 目标选中后以标签替换范围选择器；同一个“第 N 页”不能同时在选择器和标签中重复展示。
- 老师发送修改要求后，消息立即以老师气泡进入时间线；服务端响应回来后由持久消息替换，不等待 AI 完成才显示输入记录。
- 清除目标后取消右侧选中态并禁用发送按钮。
- 课后词汇匹配由程序派生，不提供 AI 修改；页面提示老师修改对应正文词汇。
- AI 响应 Schema 只允许返回目标范围。

上下文按目标最小化传递：

| 修改目标 | AI 上下文 |
| --- | --- |
| 单章正文 | 目标章结构化正文、全课章节标题与摘要、本章词数、段落数、知识点与正文题量 |
| 单个正文段落 | 目标段落、同章 clean text、必须保留的题型、题量和知识点映射 |
| 章节练习分页 | 本章 clean text、知识点、当前题型分页和约束 |
| 课后语法分页 | CEFR、课后所选知识点、当前题型分页和约束；不传课文 |
| Main Idea | 全课 clean text 和当前 Main Idea |

单题修改只能改写题干、答案、干扰项和情境，必须保持题型和绑定的语法知识点不变。修改题型、题量或知识点必须返回 Step 3。

保存使用简单安全规则：

- AI 生成和校验成功后才覆盖目标内容；失败时保留当前内容。
- 不建设历史版本或恢复界面。
- 后端比较规范化内容哈希；没有实际变化时不覆盖，也不标记下游过期。
- 正文变化后只把第二阶段练习标记为过期；Main Idea 与正文修改完全隔离，不标记过期、不自动联动。
- 第二阶段练习变化后，视觉资源标记为过期，但不自动重新生成。
- 存在过期依赖时不能最终确认，老师明确触发重新生成后才产生费用。

## AI 模型

Step 4 的模型选择与 Step 2 独立：

- 默认 GPT。
- 界面只显示稳定产品名 `GPT`，不显示具体版本、默认标记或能力后缀；底层型号由服务端配置，模型升级不改界面文案。
- 老师可以切换为 DeepSeek 以降低成本。
- 选择保存在 Step 4 设置中，刷新后保持。
- 生成中不能切换。
- 首次生成、自动修复、Main Idea 和第二阶段练习使用当前选定模型。
- 系统不自动切换模型；老师手动重试前可以更换。
- 老师和学生的人物信息传给 Step 4 AI 时只暴露英文名；已确认大纲中出现的对应中文名先由程序替换为英文名，不把中文名发送给模型。

## 生成策略

### 任务专用最小 Prompt

禁止把完整 `TeachingPlanState` 展开给所有任务。每种任务单独构造白名单 context：

- 首次正文：故事标题、课程英语难度、英文人物名；每章 id、顺序、标题、摘要、目标词数、段落数、语法点完整来源上下文和三种正文题量；课后阅读目标词数及按目标值动态计算的优先范围、验收范围。
- 练习生成：课程英语难度；每章 id、标题、clean text、语法点完整来源上下文和章节练习题量；课后只含启用状态、语法点完整来源上下文和题量。
- 正文修复：失败章节规格、当前失败内容、具体问题、全部章节标题与摘要；不传成功章节正文或 Main Idea。
- Main Idea 修复：当前 Main Idea、问题和词数范围；不传正文。
- 练习修复：只传失败目标；章节目标携带本章 clean text，课后目标不携带正文。
- 老师修改：按“教师修改”表格传递单个明确目标，不复用生成 context。

所有会生成或改写英文的任务都必须显式携带 CEFR：首次正文、正文修复、课后阅读修复、章节与课后语法练习生成、练习修复，以及老师对正文、段落、练习或课后阅读的局部修改。格式机械修复不得改写英文语义，因此只复用原始输出和 Schema，不重新决定难度。

CEFR 写作档案由服务端代码确定并随最小上下文发送，不由模型自行猜测，也不增加独立 AI 调用。相同故事大纲在不同等级下必须保持核心剧情一致，只改变英文表达复杂度。

所有 Prompt 均不传 `touched`、流程状态、推荐理由、原始知识点 ID、无关题型配置或完整 outline/plan。语法点使用稳定短键和 `resolveGrammarContext` 返回的权威来源上下文。新增上下文不得覆盖或删减现有的故事事实优先、英语自然度、叙事时间线、clean text、固定槽位、题量、覆盖、答案重建、校验、格式修复、业务修复和重试规则。

### 整体首生成 + 批量局部修复

正文首次生成：

1. 一次请求、一个响应 Schema 同时生成全课所有章节的结构化正文、正文题和 Main Idea，降低重复输入成本并保持故事连续。
2. 后端按章独立校验并持久化通过的章节。
3. 汇总所有失败章节和问题。
4. 一次修复请求只处理全部失败章节，已通过章节不重写，只提供必要相邻故事上下文。
5. 修复后再次统一校验。
6. 课后阅读独立校验；不符合 Step 3 目标值上下 10 词、且收敛在 80-150 词内的动态验收范围时，只修课后阅读，不改正文。

如果响应 JSON 或 Schema 无法解析，先把原始输出、目标 Schema 和解析错误交给 AI，只修格式、不重新创作内容；明显截断时才重新执行首次整体生成。

章节正文修复只返回失败章节，保持 Main Idea 不变。章节练习与课后语法练习首次使用同一个精简请求；修复时一次处理全部失败目标，但每个目标只携带自己的正文或课后约束。

每个生成阶段最多进行 2 轮自动批量修复。两轮后仍有问题时停止自动调用，保留成功内容，并由老师明确点击再次修复。

### 左侧进度消息

进度消息由程序根据真实状态生成，不额外调用 AI，也不能伪装成老师输入。

示例：

```text
正文已生成，正在检查内容。

检测到 3 项需要调整，正在自动修复：
1. 第 2 章未完整覆盖“一般过去时”
2. 第 3 章有 1 道词汇题无法安全嵌入正文
3. 第 4 章正文比目标长度偏短

正文与 Main Idea 已生成，正在分别检查。
```

只展示教师能理解的章节和业务原因，不展示数据库 ID、`optionCloze` / `wordForm` 等内部枚举、JSON、schema、provider 原始错误或 raw output。教师侧的知识点显示系统英文标题和 Unit 范围，必要时可查看书名、版本与来源 Unit；题型显示“选项填空”或“给词变形”，数量问题同时显示要求数量和实际数量。同一次检测只追加一条问题汇总，刷新和轮询不能重复写消息。

进度消息直接进入聊天时间线，不另设重复的流程卡。开始正文和重试只作为操作按钮，不伪造老师输入；“确认正文与课后阅读，生成练习”代表老师确认第一阶段成果，必须保留一条老师记录且一次生成任务只写一次。最终进入视觉资源只使用页面底部“下一步：视觉资源”：点击后直接确认保存并跳转，不向聊天时间线追加确认记录、保存状态或确认操作卡。

## Loading 与恢复

首次整体响应返回前不能伪造逐章结果。右侧立即展示已知目录项、章节标题和内容页骨架屏，左侧显示真实阶段：

- 正在准备课程内容。
- 正在生成正文、正文练习与 Main Idea。
- 正在检查各章内容。
- 正在修复指定章节。
- 正在检查或单独修复 Main Idea。
- 正在生成章节练习。
- 正在生成课后练习。
- 正在整理课程内容。

页面显示已等待时间，不显示虚假的完成百分比或剩余时间。首次响应回来后，已通过章节立即渲染，待修复章节继续显示骨架或问题状态。

Loading、错误和修复状态统一使用内容宽度的助手气泡，不横向铺满聊天栏。老师点击重试后，旧错误必须随新请求开始立即移除，不能等待下一次轮询再消失。等待超过 2 分钟时说明长篇内容仍在生成；超过 5 分钟时明确“仍在等待本次结果，不会自动重复提交”。

正文、练习、重新生成和局部修改分别显示任务阶段：准备约束、AI 生成、结构与业务校验、最小范围修复和保存结果。局部修改必须恢复并展示具体目标，例如“第 3 章 · 正文第 2 页”，不能统一写成“正在按指定范围修改内容”。重新生成期间明确旧版本在新结果通过前保持不变。

工作台底部操作栏参与“标题 / 双栏 / 底栏”布局，不使用覆盖聊天输入区或预览区的 sticky。窄宽度使用聊天 / 预览单面板切换；可用宽度达到最低双栏宽度后启用紧凑双栏；宽屏只调整栏宽比例，不复制另一套状态和交互。

老师刷新、离开文案与练习环节或稍后返回时，页面通过持久任务状态和轮询恢复。刷新只能读取状态，不能重新提交生成请求。正文、练习和聊天修改都必须持久化当前 operation；不能只依赖浏览器内存中的 loading 状态。

每个运行中 operation 持有数据库租约并定时续约。服务进程退出、部署中断或任务失去心跳后，读取状态时必须原子地把过期任务标记为“结果未确认”，恢复操作前的内容状态并解除界面锁定。页面向老师说明本次处理没有完成确认，并提供重试或重新开始；不得无限显示“生成中”。

老师可以显式重新生成“全部章节正文 + Main Idea”或“章节与课后练习”。当前课程已经产生视觉资源或预览发布设置时，重新生成前提示这些成果不会自动更新或删除；老师确认后领取幂等生成任务，新结果成功后把视觉资源及预览发布标记为旧版本。生成失败时保留当前内容和全部后续成果。

## 状态与幂等

```ts
type ContentGenerationStatus =
  | "empty"
  | "reading_generating"
  | "reading_repairing"
  | "reading_ready"
  | "exercise_generating"
  | "exercise_repairing"
  | "exercise_ready"
  | "content_confirmed"
  | "failed";
```

防重复规则：

- 前端提交后立即禁用对应操作。
- 客户端使用 `Idempotency-Key`。
- 同一课程、同一上游内容版本、同一 operation 只允许一个有效生成任务。
- 同一课程任意时刻只允许一个正文、练习或聊天修改写任务；领取任务和绑定当前 operation 必须在同一个数据库事务中原子完成。
- 每个任务记录开始时的 `contentVersion`、操作前状态、租约到期时间和唯一 operation ID；运行期间持续续约。
- 所有阶段更新和最终写入必须同时匹配当前 operation ID 与开始时的 `contentVersion`。重新开始或其他操作使任务失效后，迟到的旧结果不得写回。
- 聊天修改只更新目标字段；不得把请求开始时复制的整份旧章节覆盖回数据库。
- 已成功 operation 的重复请求直接返回已有状态。
- 所有 AI 生成请求默认超时统一为 600 秒。文本请求可通过 `TEXT_GENERATION_TIMEOUT_MS` 调整，全部章节正文与 Main Idea 的合并请求可通过 `COURSE_CONTENT_GENERATION_TIMEOUT_MS` 单独覆盖，图片请求可通过 `IMAGE_GENERATION_TIMEOUT_MS` 调整。
- 只有能确认“请求尚未到达模型”的连接错误才允许自动重试。
- 请求可能已经到达模型但响应丢失时，不自动再次付费生成，标记为结果未确认并交给老师决定是否重试。
- 老师在超时或结果未确认后点击重试，会创建一次新的 AI 请求；系统继续复用已经持久化成功的章节或课后阅读，不重复生成已成功目标。首次整包响应尚未返回时没有可安全拆出的部分结果，不能伪装成已保存章节。
- 内容成功、任务成功与解除当前 operation 必须在同一个事务中提交；内容确认与课程阶段推进也必须在同一个事务中提交。
- “重新开始”在运行中仍可使用。确认后立即使当前 operation 失效，只清理本环节数据；视觉资源、图片和预览发布设置保留为旧版本。旧请求即使稍后返回也不能恢复已删除的当前内容。

MVP 继续使用 Next.js 单体、PostgreSQL 持久状态和前端轮询，不引入 Worker、MQ 或 WebSocket。

## 硬校验

第一阶段至少校验：

- 章节 ID、数量和顺序与大纲一致。
- 每章实际 clean text 词数在目标值上下 10% 内。
- 段落数等于 Step 3 已确认的 `paragraphCount`。
- 每段非空且题目分布不过度集中。
- 三种正文题型数量精确匹配 Step 3。
- 正文语法题只绑定本章知识点。
- 本章每个语法知识点至少被一道正文语法题考查。
- 0 知识点章节不得出现语法 exercise part，词汇 part 继续按 Step 3 数量校验。
- 词汇题不含 `knowledgePointId`，并具有 answer、canonicalForm 和 meaningZh。
- 选项填空恰好有两个不重复干扰项，且都不同于答案。
- 给词填空具有 `baseForm` 和唯一答案；`baseForm` 是括号中的提示词，`answer` 以完整句子的语法正确性为准。句法需要原形时允许 `answer === baseForm`，也允许情态动词加原形，不得为了制造“变形”而拒绝正确答案。
- parts 能无歧义拼接为 clean text。
- 不出现 exercise part 重叠或空答案。
- 课后阅读符合 Step 3 目标值对应的动态验收范围且结构完整。

第二阶段至少校验：

- 题型和题量精确匹配 Step 3。
- 章节练习只绑定本章语法知识点，并独立覆盖全部本章知识点。
- 0 知识点章节不得存在章节语法练习。
- 章节练习题句不得与任一课文原句完全相同；高相似度内容进入修复。
- 课后语法题只绑定课后所选知识点，并独立覆盖全部课后知识点。
- 所有选项填空均能由答案加两个干扰项编译为 3 个唯一选项。
- 所有题目具有固定答案。
- 词汇匹配去重、页内闭包、分页和答案映射完整。

CEFR 自然度、故事冲突和题目质量主要通过 Prompt、批量修复和老师检查保证；服务端不得伪装成能够以简单规则完全判断语义质量。

## API 边界

本模块 API 统一使用正式 `/api/courses/:id/content` 路径。

### `GET /api/courses/:id/content`

读取 Step 4 状态、设置、内容、生成进度、消息和问题卡。轮询只调用该接口。

### `PUT /api/courses/:id/content/settings`

保存 Step 4 模型选择。生成中拒绝修改。

### `POST /api/courses/:id/content/reading/generate`

创建或返回已有的第一阶段生成任务。必须使用幂等键，并严格读取已确认 Step 2 和 Step 3。
显式重新生成时使用 `?regenerate=true`；如存在视觉资源或预览发布成果，先提示它们会保留为旧版本。确认后重新生成当前内容，不删除下游成果；生成失败不改变下游。

### `POST /api/courses/:id/content/exercises/generate`

确认当前第一阶段结果并创建第二阶段生成任务。第一阶段存在缺失、失败或过期内容时拒绝。
显式重新生成练习时使用 `?regenerate=true`；如存在视觉资源或预览发布成果，先提示它们会保留为旧版本。练习生成成功后标记后续旧版本；生成失败保留当前练习和全部下游成果。

### `POST /api/courses/:id/content/modify`

按显式 `targetType + targetId` 修改正文、Main Idea、题型组或单题。响应 Schema 只能覆盖目标范围。

### `POST /api/courses/:id/content/retry`

由老师明确重试已停止自动修复的问题，可在请求前更换模型。不得重新生成已通过目标。

### `POST /api/courses/:id/content/reset`

清空当前课程全部文案与练习聊天消息、生成任务、正文、Main Idea、章节练习和课后练习，并回到文案与练习未开始状态。基础信息、故事大纲、已确认教学规划、视觉资源、图片和预览发布设置保持不变；后续成果标记为旧版本。删除操作失败时不开始新的生成任务。弹窗只说明当前阶段会删除的内容，操作为“取消”和“删除文案与练习并重新开始”。

### `POST /api/courses/:id/content/confirm`

校验全部正文、Main Idea、启用的章节练习和可选课后练习；不存在过期依赖时更新为 `content_confirmed` 并进入视觉资源。

## 数据边界

当前实现使用以下稳定领域表：

- `CourseLessonContent`：课程级状态、模型设置、Main Idea、章节/段落/习题结构和当前内容版本。MVP 将强一致的聚合内容保存在 JSON 中，内部仍使用稳定章节、段落和习题 ID；避免生成成功后跨多表部分写入。
- `CourseContentGeneration`：operation、上游版本、状态、尝试次数、模型和幂等键。
- `CourseContentChatMessage`：老师消息、助手状态和系统进度；系统进度不进入 AI 修改上下文。

程序生成的 clean text、页数、题号、横线、选项顺序和课后词汇匹配均应有明确 source hash 或确定性派生规则，不能由多个字段各自维护真相。

## 下游边界

- 返回较早环节查看不清理数据。
- 修改基础信息、故事大纲、教学规划或文案与练习时，后续成果全部保留，只从最早受影响阶段开始标记为旧版本。
- 重新生成正文或练习前提示视觉资源、图片和预览发布设置不会自动更新，也不会被删除；生成成功后标记后续旧版本。
- “重新开始”只清空文案与练习当前阶段；视觉资源、图片和预览发布设置保持不变。
- 已发布课程出现旧版本内容时退回未发布状态，但保留原课程内容和设置。
- 当前阶段删除失败时不开始生成、不改变旧版本状态，并在触发操作旁展示错误。
- 视觉资源只读取 clean text、稳定段落 ID、角色卡和故事大纲，不读取学生版挖空文本。

## 验收标准

- Step 4 使用“正文与内嵌题联合生成 -> 章节与课后练习生成”的显式两阶段流程。
- 完整阅读和边读边练由同一份 parts 编译，图片始终读取 clean text。
- 正文、章节练习和课后语法练习分别独立覆盖配置的全部语法知识点。
- 0 知识点章节仍生成阅读和词汇内容，但不生成或校验语法题。
- AI 接收书名、版本、官方书籍等级和全部来源 Unit，同时保留此前已确认的 Prompt 优先级与修复规则。
- 词汇题不绑定语法知识点；课后词汇匹配由正文词汇自动汇总去重，不调用 AI。
- 章节练习改编课文情境但不复制原句，不与课文事实冲突。
- 课后阅读是默认约 120 词、可在 Step 3 配置目标词数的全故事纯阅读摘要，不带题目或高亮。
- 正文和 Main Idea 首次由同一个 Prompt 生成；后续自动修复和老师修改始终按目标隔离，不互相联动。
- 右侧用一个紧凑内容选择器切换章节正文、章节练习、Main Idea 和可选课后练习；预览区一次展示一张不产生内部滚动的 16:9 最终内容页。
- 语法题和匹配题的单页容量均为 5，超过后按最少页数均衡分配；匹配题答案不跨页。
- 完整阅读高亮语法和词汇锚点，词汇后紧跟中文释义，语法不追加释义；边读边练不显示正文题号，答案按页就近展示。
- 所有选项填空由一个答案和两个干扰项编译为 3 个无编号选项。
- 左侧显示真实检查和批量修复消息，不伪装老师输入，不展示技术错误。
- 首次整体生成、按章校验、批量局部修复最多自动执行 2 轮。
- 刷新、离开页面、重复点击或重复请求不会重复产生 AI 费用。
- 服务进程退出或任务租约过期后，页面不会永久卡在处理中；老师可以重试或重新开始。
- 刷新修改页面或多标签页同时操作不会并发覆盖；过期版本和迟到结果会被拒绝。
- 右侧只读，老师通过显式范围的聊天修改；修改失败不覆盖当前内容。
- 从左侧修改范围选择任一页面后，右侧必须同步切换到所属章节、内容类型和准确页码；不能只更新输入框标签。
- Step 4 可独立选择模型，默认 GPT，不自动切换模型。
- Step 4 支持独立清空全部记录并重新开始，不影响 Step 1-3；失败时不丢失旧结果。
- 已确认的 Step 4 再次打开时，必须保留顶部 Step 5 链接和底部“下一步：视觉资源”；不能只依赖可能滞后的 `course.currentStage` 判断可达步骤，也不在聊天区重复显示跳转记录。
- 最终确认前不存在缺失、失败或过期内容。

## 分章固定槽位实验（`codex/step4-slot-experiment`）

### 实验目的

本实验只验证是否能用更小的 AI 输出和更小的失败边界，提高 Step 4 每次用户操作后的整课可用率。实验不直接替换当前生产流程，也不为了比较方案而批量重复生成完整课程。

实验方案保持“正文与题目联合生成”，不增加 AI 知识点规划阶段：

```text
整课一次生成正文模板 + 每章固定命名槽位（共享故事上下文）
-> 程序编译为现有 CourseContentPart[]
-> 按章校验并保留成功结果
-> 普通失败只返回单段/单题补丁，结构损坏最多只重生该章
-> 全部章节通过后单独生成 Main Idea
```

正文模板使用稳定槽位标记，例如 `{{WF1}}`。AI 同次返回槽位的答案、题型字段、知识点短键和答案回填后的原文证据；程序确定性地检查要求槽位与实际槽位完全一致、证据确实位于题目所在段落，并对可机械识别的语法结构做二次校验，再将模板编译为现有顺序 parts。下游 Preview、PDF、视觉资源和持久化课程内容继续消费现有结构，不感知实验输出契约。

给词填空在产品语义上统一为“有提示词的语境填空”，不要求答案必须发生字面变形。`cue` 可以保持原形、发生词形变化，或与空格旁的情态词、助动词和从句结构共同构成知识点。因此 57 个现有语法知识点都可与选项填空、给词填空混合使用，不增加 Step 3 前置过滤器；但每个语法槽位必须给出至少两个词的 `evidenceExcerpt`，不能只贴知识点 ID。

篇幅控制同时使用两层边界：每章继续按目标词数的动态范围验收；生成前再把目标均分为明确的每段 `preferredRange` 和 `acceptedRange`。例如目标 120 词、2 段时，要求每段优先 55–60 词，硬边界 53–75 词。模型输出上限只防止响应失控，不能替代正文词数校验。

### 成本控制

- 契约解析、模板编译、槽位唯一性、缺失与多余槽位、知识点覆盖、词数计算和修复退化保护全部使用本地 fixture 测试，不调用 AI。
- 不执行完整课程双跑或后台 shadow generation；同一份用户请求不能为了实验同时调用旧方案和新方案。
- 真实 AI 验证从一个历史失败章节开始，只验证新契约能否一次满足段落、槽位、知识点和词数约束。
- 首轮正式方案只调用一次整课生成，共享故事、人物和 CEFR 输入；每章独立编译和验收。失败章最多一次自动修复，未通过则停止并保留其余成功章节。
- 单章通过后最多再验证 3 个具有不同 CEFR、知识点数量或题型比例的章节；是否继续由已记录的 token 和业务问题决定。
- 实验调用必须记录 input、visible output、reasoning 和 total tokens，并设置低 reasoning 与按单章估算的输出上限。
- 后续正式评估使用真实新课程的单路 canary，不对同一课程额外生成旧方案基线；旧方案基线使用已有失败记录和后续自然流量统计。

### 决策指标与停止条件

每个章节分别记录首次校验问题、修复后问题和 token。只有同时满足以下条件，才讨论接入正式生成流程：

- 固定槽位数量和 ID 能被程序确定性闭合，不再出现匿名计数误差。
- 自动修复不新增已通过指标的问题；不满足时拒绝覆盖旧结果。
- 单章生成加目标修复的总输出量明显小于当前整章重复重写的输出量。
- 故事事实、CEFR 自然度和知识点真实用法经老师检查不低于当前方案。

出现以下任一情况立即停止真实调用并回到离线设计：

- 连续 2 次单章调用仍无法满足固定槽位契约。
- 新契约虽然结构通过，但正文自然度或知识点用法明显下降。
- reasoning 或重复输入成本抵消了局部输出节省。

### 2026-08-22 单章真实实验结论

使用生产失败课程 `cmt2pyilp000fggwms0fpthv3` 的第 5 章输入，通过 Crazyrouter GPT 执行了一次低 reasoning、`max_output_tokens=2200` 的单章模板实验。本次不执行自动修复或第二次生成。

### 2026-08-22 离线闭环修订

单章真实实验后不再调用 AI，完成以下修订：

- 不采用五次独立单章首轮调用。真实失败案例中，五份单章请求合计 19,090 字符；整课共享上下文请求为 6,053 字符，输入字符减少 68.3%。该数据只说明相对输入规模，最终计费 token 仍必须以后续一次 canary 的 provider usage 为准。
- 固定槽位契约补齐 `cue` 和 `evidenceExcerpt`；`Future with Will`、`Must`、进行时等可机械识别结构会在本地拒绝“ID 正确、语义错误”的结果。57 个当前启用语法点全部进入统一的题型指导分类，不因题型组合被前置删除。
- 目标 120 词、2 段时，首轮明确给出每段优先 55–60 词、允许 53–75 词；本地同时检查逐段和整章词数，解决“总词数提示存在但单章仍写到 199 词”的控制缺口。
- 自动修复分两级：词数或证据错误只接收段落/槽位补丁；章节 ID、段落数、槽位集合或 parts 结构损坏时，最多重生该失败章。任何候选修复若新增问题，或问题集合没有严格缩小，均拒绝覆盖旧结果并停止自动修复。
- 编译只按稳定章节 ID、槽位 ID 匹配，禁止按数组位置补齐。一个章节缺失或失败不会错配、覆盖其他章节。
- 整课响应先解析外层，再逐章执行严格 Schema；单章字段损坏只标记该章失败，其他合法章节继续编译和保留。外层 JSON 本身截断仍属于整次请求失败，因此正式调用必须使用足够输出上限，不能依赖自动续写。

离线阶段能证明结构、计数、范围、证据归属、失败隔离和修复单调性，不能证明模型在所有故事和所有语法点上的自然度。原实验结论建议下一次付费验证只做一次整课 canary，不做新旧方案双跑；但按 2026-08-24 的正式范围决策，本轮不执行付费 canary，转为后续 TODO。届时请求固定 low reasoning、`max_output_tokens=6500`；上限用于防止失控，不代表必然消耗，并记录 provider usage、逐章首次通过率和本地问题明细。

### 2026-08-24 正式优化范围决策

本轮优化的北极星指标为首次整课可用率、可扩展性和单位成功课程成本。实现范围收敛为：程序固定章节、段落和题型槽位等结构不变量；AI 负责知识点分配、自然语境、答案和干扰项；首轮继续采用单次整课生成；响应按稳定章节与槽位 ID 独立解析；成功章节不可被后续修复覆盖；失败只允许按单章、单段或单槽位最小修复，且最多自动修复一次。程序不得自动改写、补写或压缩 AI 生成的英文语义内容。

本轮不实现以下能力，统一记录为后续 TODO：

- TODO：统一优化知识点数据质量，为每个知识点补齐稳定 code、定义、正例、常见错误和题型指导；本轮继续使用现有知识点数据，不为每个知识点新增专属程序规则。
- TODO：根据章节数、目标词数、槽位数和知识点上下文动态拆分生成批次；本轮保持一次整课生成，失败后只处理失败目标。
- TODO：引入独立 AI Critic 或生成后的语义复核调用；本轮不增加固定 Critic 成本，只要求生成模型在同一次调用内完成不输出过程的自检。
- TODO：建设需要真实线上 AI 请求的持续评测或 canary；本轮不做新旧方案双跑，也不把付费真实 AI 回归放入日常测试。

本轮验证以本地确定性测试为主，覆盖固定槽位闭合、缺章、重复或未知 ID、逐章容错解析、词数计算、成功章节保留、最小补丁边界、修复不退化、迟到结果拒绝和调用次数上限。少量人工触发的真实 AI 验证应与日常自动测试分离，是否执行及样本数量另行确认。

生成协议已增加轻量 `contractVersion`；该字段只用于识别生成请求、响应和修复补丁是否属于同一协议，不代表生产同时维护 V1/V2 两套实现，也不进入 Preview、PDF 或长期课程内容领域结构。
