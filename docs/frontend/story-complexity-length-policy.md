# 故事复杂度与中英文篇幅统一策略

## 目标与边界

本策略只解决一个问题：在不改变老师已确认要求、学习目标、事实 / 忠实边界和点名角色的前提下，让故事结构与中英文可用容量相匹配。它是 Step 2、Step 3、Step 4 的共享领域规则，不是新的大纲语义 schema。

- Step 1 不再有课程时长概念；遗留 `durationMinutes` 只为旧数据兼容，不进入篇幅计算或 Prompt。
- 复杂度是结构上限，不是结构配额。任何档位都只有一条主要主线，不要求机械加入冲突、失败或反转。
- 方向和大纲继续复用 `hook`、`storyHighlight`、`growthCore`、`whyFits`、`outline.summary` 与 `chapter.whatHappens`。
- 中文没有强制下限，也不得程序截断；方向、大纲与单章修改在解析后确定性计算非空白 Unicode 字符数，超过生成上限时整步失败并沿用现有手动重试，不保存截断内容、不增加自动 AI 调用。
- 每章采用相同英文目标，章节数只改变全课总容量，不改变单章目标。
- 旧课程不因读取状态而改写。新规则只影响新生成、主动重生成和新建 / 重置规划。

## 故事复杂度

| 值 | 老师文案 | 结构上限 |
| --- | --- | --- |
| `clear_linear` | 精简·清晰线性 | 儿童童话式的一条线性主线；目标、行动和结果直接 |
| `conflict_driven` | 标准·冲突推进 | 一条主线；允许一个核心矛盾、受挫、选择或策略调整 |
| `layered` | 丰富·多层叙事 | 一条主线；允许复杂动机、信息回收和有铺垫的反转 |

默认值：Starter / A1 / A2 为 `clear_linear`，B1 / B2 为 `conflict_driven`，C1 / C2 为 `layered`。老师可在 Step 2 修改；修改不会改变上游硬要求，也不会授权 factual / faithful 内容虚构事件。

## 英文单章策略

表内为每章目标词数：

| CEFR | clear_linear | conflict_driven | layered |
| --- | ---: | ---: | ---: |
| Starter | 80 | 100 | 120 |
| A1 | 100 | 120 | 140 |
| A2 | 120 | 140 | 160 |
| B1 | 140 | 170 | 200 |
| B2 | 160 | 190 | 220 |
| C1 | 180 | 210 | 240 |
| C2 | 200 | 230 | 260 |

由目标值派生：

- 生成与验收允许波动：共享纯函数根据任意最终目标计算 `88%–115%` 并四舍五入到 10 词。Step 2 默认目标和 Step 4 老师最终目标调用同一函数。
- 老师推荐调整范围：`目标 - 30` 到 `目标 + 40`。
- 老师硬边界：`60–360`；范围外阻止确认。
- 推荐范围内正常；低于推荐范围提示“可能无法完整表达本章事件”；高于推荐范围提示“可能增加学生阅读负担”。提高词数不会提高故事复杂度。

## 中文策略

表内为“Prompt 推荐上限 / 确定性生成上限”，均无下限：

| 复杂度 | 方向 `hook` | 大纲 `summary` | 单章 `whatHappens` |
| --- | ---: | ---: | ---: |
| clear_linear | 80 / 120 | 110 / 160 | 65 / 100 |
| conflict_driven | 95 / 140 | 130 / 190 | 80 / 120 |
| layered | 110 / 160 | 150 / 220 | 95 / 140 |

语义职责：

- `hook`：2–3 个短句，说明开端、主要发展和结果方向，是老师可快速读懂的故事概要，不是隐藏结局的营销悬念。
- `storyHighlight`：只写本方向的辨识度。
- `growthCore`：老师侧名称为“成长与理解”；每个故事只选择最自然的一个主题，如自我效能、情绪识别、同理心、合作、成长型思维、边界或独立判断，不说教。
- `whyFits`：只解释与老师要求和英语难度的匹配。
- `outline.summary`：3–4 个清楚短句，完整概括开端、发展、关键行动与结果。
- `chapter.whatHappens`：每章一个主要剧情作用，说明承接局面、主要行动与结果。

## 内容优先级

- `narrative`：叙事目标优先，复杂度只限制结构。
- `concept`：理论 / 概念目标优先，包装不足时简化故事，不牺牲概念准确性。
- `factual`：事实与已确认因果优先，不因复杂度虚构冲突、动机或反转。
- `faithful`：原作 / 史料的既定事件、因果、角色行为与结局优先；复杂度只改变讲述组织，不改变事实。

## Step 2 → Step 3 → Step 4 数据流

1. Step 2 保存 `storyComplexity`，按课程 CEFR 解析共享策略，将中文边界与每章英文容量发送给方向 / 大纲 Prompt；老师不在此配置词数。
2. Step 3 用相同策略初始化每章 `targetWordCount`，展示推荐范围和非阻断提示，只有 `60–360` 外阻止确认。已保存旧规划不自动归一化。
3. Step 4 读取同一策略与老师最终 `targetWordCount`，再用共享纯函数重新计算该最终目标的生成、段落预算、验收与修复范围。CEFR 控制英文表达，复杂度控制结构上限；修复 Prompt 同样禁止因补词增加剧情机制。

## 两轮回归实验

本轮没有调用项目配置的 AI、联网研究或任何付费 API。样例由本 Codex 任务生成并审阅。

### 第一轮：旧规则基线

将模块文档中的 16 个历史案例和 13 个新边界维度放回旧规则检查，主要失败为：

- `durationMinutes × CEFR` 与 `120–200` 截断把 Starter、C1、1 章、8 章压成相近容量，课程时长错误控制篇幅。
- Step 2 不知道后续英文容量，方向 / 大纲容易超出正文承载能力。
- `hook` 隐藏结果，老师无法快速复述；中文只有零散经验值，没有集中硬上限。
- “复杂故事”容易被理解为必须增加冲突或反转；concept / factual / faithful 缺少内容优先级护栏。
- Step 3 的旧草稿读取会自动归一化，违反旧课程只读原则。

据此形成统一二维矩阵、中文上限、复杂度上限原则、四类内容优先级和旧课程不改写规则。

### 第二轮：统一规则重复回归

使用 `lib/domain/evals/story-complexity-regression.fixture.ts` 的 29 个可审计样例重复检查，测试暴露并修复：

- 调用方未显式传 `lengthPolicy` 时，Step 2 Prompt 一度输出 `null` 容量；现按 CEFR / 复杂度确定性解析。
- 历史课程缺少英语等级时，旧回退会误落到 `layered` 并查表失败；现只读回退为 A2 / clear_linear。
- Step 3 旧测试仍期待自动把 90 词抬到新下限；现锁定旧规划保持 90，新建 / 重置才使用新目标。
- 历史 Prompt 断言仍要求课程时长和营销式悬念；现改为明确断言生产 Prompt 不含课程时长与历史案例名。
- 二次审查发现 Step 4 曾使用“下浮 12%、上浮固定 30 词”的独立公式；现已删除，80、170、260 和老师自定义 90 词均由共享函数生成相同范围。
- 中文上限原先只有 Prompt 约束；现对方向生成 / 修改、整体大纲、单章生成 / 修改执行确定性校验，超限走现有失败与手动重试边界，不截断、不追加 AI 调用。

最终 fixture 覆盖全部 16 个历史案例和 13 个新案例，包含 narrative / concept / factual / faithful、Starter–C1、三档复杂度、单人 / 多人 / 八名学生、科学概念、儿童心理主题、信息密集 / 事件密集、真实历史多视角以及 1 / 8 章边界。

## 证据口径与不确定性

自动化结构验证能证明：矩阵与默认映射一致；Step 2 默认目标与 Step 4 最终目标复用同一范围函数；Prompt 没有课程时长与案例名；fixture 覆盖完整；方向、summary 和 whatHappens 超过生成上限会被拒绝且不会截断保存；旧数据不被自动改写。

fixture 中的 `semanticReview` 是本 Codex 任务对固定样例逐项做出的语义判断，能提供可审计回归基线，但不能证明任意生产模型输出稳定，也不是一次真实模型 A/B。仍需老师在真实工作台验证：三档复杂度是否容易理解、提示是否会干扰编辑、八人群像的可读性、低等级科学概念是否自然，以及不同生成模型对中文上限的遵守程度。
