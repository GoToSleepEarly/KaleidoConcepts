# 课程列表管理模块说明

## 模块目标

本模块覆盖 MVP 的课程列表管理首页，入口为 `/courses`。

本期目标是让教师能基于真实后端数据查看已创建课程，并进入编辑、预览或从列表删除。

## 本期范围

包含：
- 课程列表管理页面
- 课程空状态
- 课程状态展示
- 课程基础信息展示
- 课程绑定老师展示
- 课程编辑入口
- 课程预览入口
- 课程删除确认与可恢复归档
- `GET /api/courses` 后端接口
- `DELETE /api/courses/:id` 后端接口
- Prisma 数据模型与查询映射
- 开发种子数据

不包含：
- 新建课程 Step 1-5 的开发
- 已删除课程恢复入口
- 课程物理删除
- 状态筛选
- 批量操作
- 服务端 PDF 渲染
- 图片生成流程
- 状态筛选

## 页面结构

AppShell header 显示 `课程列表`，内容区不重复大标题。

内容区顶部：
- 左侧说明：`管理已生成和制作中的课程。`
- 右侧按钮：`新建课程`

课程列表：
- 有数据时使用表格型列表
- 无数据时显示空状态
- 不做状态筛选

采用表格型列表的原因：
- 课程是管理对象，未来会扩展状态、时间、学生、操作等字段
- 相比卡片更适合扫描和比较

## 课程首页视觉优化方案（2026-08-13）

本轮只调整 `/courses` 与其直接使用的 AppShell，不改变课程数据、接口、状态流转或其他业务页面。不得新增可见说明文案。

### 视觉方向

- 定位为“明亮学习工作室”，保留产品工具的清晰与克制，不使用深色后台模板风格。
- 页面底色使用带轻微蓝色倾向的近白色；导航、页头与课程列表使用白色或浅蓝表面。
- 紫蓝色只用于主操作和当前导航；薄荷绿、浅黄色只用于状态，不把整页做成高饱和彩虹色。
- 少儿感来自明亮色彩、清晰图标和轻快比例，不新增装饰文案、营销口号或无功能插画。

### AppShell 统一规则

- 桌面与 iPad 横屏侧栏宽度统一为 240 px，改为明亮浅色导航；品牌、导航文字和图标全部使用深蓝灰文字体系。
- 品牌区与顶部栏高度统一为 72 px，左侧品牌名 15–16 px semibold，辅助品牌名 12–13 px medium。
- 导航项高度 44 px、文字 14 px medium、图标 18 px；当前项使用淡紫蓝底色与主色图标，不再使用白块叠在黑底上的强反差。
- 顶部页面标题使用 20 px semibold，副标题 13 px regular；左侧导航与右侧内容遵循同一字号阶梯和字重规则。
- 账号入口和退出菜单使用相同宽度并共享左右基线。菜单紧贴入口下方 8 px，不能比触发按钮向左突出。
- 账号菜单需要支持点击外部关闭与 `Escape` 关闭；退出行为保持不变。

### 课程内容布局

- AppShell 已提供页面标题和说明，内容区删除重复的 `课程工作台` 与 `从基础信息开始，逐步完成一门课程`。

- 内容最大宽度从 1152 px 放宽到 1280 px，使六列信息在 1366 px 与更宽 PC 上有合理呼吸空间。
- 课程列表保留表格结构，但取消每个单元格独立卡片。每门课程是一条完整行，使用间距、列对齐和浅色状态标签建立层级。
- 表头统一为 13 px semibold；课程标题 15 px semibold；字段正文 14 px；辅助信息、时间与标签 12–13 px。
- 行高保持 88–96 px；课程图标使用柔和色块，操作区保持固定宽度并右对齐。
- 空状态、加载状态与错误状态继续沿用现有业务内容，只调整色彩、间距和边界，不增加说明文字。

### 横屏适配

- 本轮目标尺寸为 1024 × 768、1280 × 800、1366 × 768、1440 × 900 和 1920 × 1080。
- 1024–1199 px 保留桌面侧栏与顶部栏，课程列表允许将次级字段收紧，但不得产生页面横向滚动。

## 课程字段

列表展示：
- 课程标题
- 故事题目：优先展示当前故事大纲标题；未生成时显示“未生成故事”
- 老师英文名
- 学生英文名
- 教学配置：英语等级与课程时长，不展示语法点数量
- 当前进度：`Step n/6 · 阶段名称`
- 发布状态
- 更新时间
- 操作：编辑 / 预览（或授课）/ 删除

桌面端将相关字段组合为“课程、授课对象、教学配置、进度、状态与更新时间、操作”六列。故事标题、人物名单使用单行截断并通过 `title` 提供完整文本，避免表格超宽。小屏改为紧凑卡片，不产生横向滚动。

表头使用独立浅色标题带与较大的加粗文字，各列标题和内容共享同一网格与内边距基线。课程、授课对象、教学配置、制作进度、状态分别使用带边框的浅色信息块，其中进度和关键操作使用单一主色强调，避免整行信息无层级或堆叠过多颜色。

老师规则：
- 本期按单课程单老师处理
- 后台数据可继续用 `CoursePerson` 存储老师和学生关系
- `GET /api/courses` 对课程关联的 `role=teacher` 人物取第一个，并使用课程创建时保存的英文名快照；学生列表同样使用英文名快照

原因：
- 教案和插图生成需要一个明确老师形象
- 多老师会让 prompt、列表展示和课程编辑状态变复杂，不适合本期 MVP

状态：
- `draft`：草稿
- `building_resources`：生成资源中
- `ready`：已完成
- `build_failed`：生成失败

## API 合同

### `GET /api/courses?page=1&query=`

课程首页使用服务端分页，固定每页 5 条。未传 `page`、传入非数字或小于 1 的页码时按第 1 页处理。`query` 可选，使用课程名称与故事名称进行不区分大小写的模糊匹配。

响应：

```ts
type CoursesListResponse = {
  courses: CourseListItem[];
  page: number;
  pageSize: 5;
  total: number;
  totalPages: number;
};

type CourseListItem = {
  id: string;
  title: string;
  durationMinutes: number;
  teacherName: string | null;
  studentNames: string[];
  englishLevel: "A1" | "A2" | "B1" | "B2" | "C1" | "C2" | null;
  storyTitle: string | null;
  lessonDraftExists: boolean;
  lifecycleStatus: "draft" | "published" | "archived";
  currentStage: "audience" | "story_outline" | "teaching_plan" | "content" | "visual_resources" | "preview";
  nextEditPath: string;
  updatedAt: string;
};
```

失败：
- 数据库不可用：`500 { message: "课程列表加载失败" }`

恢复策略：
- 列表查询不修改状态，可直接刷新重试
- 页面保留错误提示和重试按钮
- 接口返回空响应或非 JSON 错误页时显示稳定的业务错误，不直接暴露 JSON 解析异常。

### `DELETE /api/courses/:id`

删除采用软归档：把 `lifecycleStatus` 更新为 `archived`，列表查询不再返回该课程，但保留课程正文、图片和生成记录，避免误操作造成不可恢复的数据损失。本轮不提供恢复入口。

成功：`204 No Content`。

失败：
- 课程不存在或已归档：`404`
- 数据库更新失败：`500 { message: "删除课程失败，请稍后重试" }`

恢复策略：接口成功后前端才移除列表项；失败时保留原列表并显示错误，不做乐观删除。

## 操作入口按状态区分（2026-07-16 更新）

背景问题：原先每行只有单个「预览」按钮恒定指向 `/courses/:id`，由服务端按状态重定向——已发布跳授课页，未发布被重定向回 Step5。导致“想进已发布课程授课要先进预览再发布”的错位，一个按钮承担了预览 / 编辑 / 授课三种语义。

新规则（每行「编辑」常驻 + 一个状态相关按钮 + 删除）：

| 课程状态 | 编辑（常驻） | 第二按钮 |
| --- | --- | --- |
| `published` | → `/courses/:id/create/preview`（回 Step6 查看或改版式） | 「授课」→ 新页面打开 `/courses/:id`，课程列表保留在原页面 |
| 未发布且已有课文草稿（可预览） | → `nextEditPath`（当前所在创建步骤） | 「预览」→ `/courses/:id/create/preview` |
| 未发布且无课文草稿（未到可预览） | → `nextEditPath` | 「预览」置灰禁用，hover 提示「请先生成课文草稿」 |

要点：
- 「预览」直接进 Step5 预览页，不再经 `/courses/:id` 服务端重定向。
- 已发布课程的「编辑」只回 Step6 查看或改版式，不回 Step1-5；仅进入页面或无差异保存继续保持已发布，实际保存修改后才转为草稿。
- `lessonDraftExists` 已在 `CourseListItem` 中返回，前端据此判断是否允许预览。
- `/courses/:id` 作为纯授课页保留（仅 published 可达，未发布仍重定向回 Step5）。
- 「删除」是独立图标按钮，打开确认弹窗后才调用归档接口，不与状态相关主操作混用。
