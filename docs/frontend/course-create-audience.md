# 课程创建阶段一：基础信息

## 模块目标

阶段一确认课程管理名称、授课老师、学生、课程时长、英语难度和全课知识点，并创建一个可恢复的草稿课程。

阶段一面向用户命名为“基础信息”。页面不展示内部工作流、数据结构或 AI 生成说明，只通过清晰布局、选择状态和必要反馈让教师完成第一步。

阶段一不配置故事、章节知识点分配、题型、题量或视觉风格。英语难度和全课知识点是老师明确给出的教学目标，也是后续流程的唯一真相源。保存基础信息本身不产生 AI 费用；人物形象生成仅在用户明确触发时产生费用。

## 路由

- 新建：`/courses/new`
- 已创建课程返回编辑：`/courses/:id/create/audience`
- 保存成功后：`/courses/:id/create/story-outline`

课程创建统一使用正式 `/courses` 路由。

## 字段

必填：

- 课程名称
- 老师：单选 1 位
- 学生：至少 1 位
- 课程时长：30 / 45 / 60 分钟，新建课程默认 60 分钟
- 英语难度：Starter / A1 / A2 / B1 / B2 / C1 / C2
- 全课知识点：至少 1 个

不在本阶段收集：

- 故事主题或参考剧情
- 第三方人物 / IP
- 题型和题量
- 视觉风格

课程名称只用于课程管理。后续故事标题或课件展示标题不得覆盖课程名称。

## 页面结构

- 顶部流程使用紧凑的分段步骤 Tab，合并到 AppShell 的“新建课程”标题行，不在正文单独占据一行。当前步骤使用品牌色实底；可返回步骤使用白底、边界、悬停和按压反馈；未解锁步骤灰化。控件自身表达可点击性，不增加说明文字。iPad 横屏隐藏步骤编号以完整显示名称，PC 宽屏显示编号和名称。
- 顶部流程图只表达流程位置和可返回节点，不展示“下一步”，下一步动作只由页面底部主按钮承担。
- 当前节点使用轻量高亮圆点和文字强调；已完成节点在已有课程 ID 的页面中可点击返回；当前节点不可点击；未解锁节点禁用。
- Step1 当前存在缺失项时，即使课程历史状态曾到达 Step2，也只突出 Step1，后续步骤不显示完成态且不可直接进入；补齐后恢复已有可达步骤。
- 顶部流程图使用中性白底和细描边，不使用说明文案、渐变装饰、大卡片、粗分割线或大面积色块，避免抢占页面主表单视觉重点。
- AppShell 在新建课程及课程创建步骤只显示当前任务标题，不显示重复解释流程的副标题。
- 页面主标题为“基础信息”。
- 页面主标题下不放解释型说明文字。
- 表单分为六个视觉重点：
  - 课程名称：带图标，突出输入框。
  - 老师：单独区域，只展示当前已选老师或“添加老师”。
  - 学生：单独区域，只展示当前已选学生或“添加学生”。
  - 课程时长：使用清晰的 30 / 45 / 60 单选控件，新建课程默认选中 60。
  - 英语难度：使用 Starter-C2 单选控件；Starter 用于零基础或刚开始接触完整英语句子的初学者。
  - 全课知识点：通过语法库弹层一次选择；弹层按语法分类提供“全部”和分类标签，搜索只过滤当前分类，跨分类选择会持续保留；已选项以紧凑标签展示。
- 六个表单区块统一使用与主题库、语法库分组一致的浅蓝顶栏，图标、标题和区块操作放在顶栏，具体输入与选择内容放在白色内容区。
- 底部提供取消 / 下一步。

页面不直接铺开全部人物卡片，不用长段说明替代可见操作。

课程名称、老师、学生、课程时长、英语难度和全课知识点均使用统一的必填 `*` 标记。老师和学生标题右侧均不显示“未选择”，完成状态通过卡片、添加按钮和底部首个阻断原因表达。

全课知识点超过 10 个时显示非阻断提示：

```text
知识点较多，当前课时可能难以充分展开。AI 会结合英语难度、课程时长和故事内容推荐每章重点，你可以在教学规划中调整。
```

该提示不替老师删除知识点，也不阻止进入下一步。

## 人物选择

- “添加老师”打开单选弹层。
- “添加学生”打开多选弹层，点击确认后应用选择。
- 支持搜索、最近使用和分页加载。
- 选择器只展示启用人物。
- 选择器使用与人物档案一致的三列紧凑资料卡，展示 2:3 人物形象、姓名、英文名、年龄和性别，避免双列宽卡产生无效空白。
- 只有存在可用当前形象的人物可以选中。无形象人物显示“形象未生成”和小型“创建形象”按钮，选择控件禁用；点击创建后在当前 Step1 内打开人物编辑弹窗，保存后返回选择器并刷新人物，不离开课程、不丢失已填内容。
- 已选人物以相同视觉结构的固定最大宽度资料卡展示，不使用横向通栏；单个老师卡也不撑满整行，老师和学生都显示真实当前形象。
- 已选卡保留固定宽度，人物信息在图片右侧居中形成稳定重心；操作区使用“编辑”和明确的垃圾桶移除图标，不使用含义模糊的 `X`。
- 人物姓名使用卡内最高信息权重，英文名和年龄性别次之；编辑、移除属于低频操作，收进右侧的小型图标按钮，不占据人物信息区。
- 已选卡的编辑、移除图标固定在卡片右侧垂直居中；人物信息区使用低饱和浅紫底。年龄和性别拆成独立的有色标签，并与人物档案保持一致，避免白色标签融入卡片背景。
- Step1 使用更紧凑的区块间距和卡片内边距；顶部步骤 Tab 提升字号与高度，作为课程创建流程的核心导航。
- 有形象的人物整张卡片就是选择控件，不再显示重复的“选择”按钮；选中态通过品牌色边界和右上角勾选标识表达。
- 无形象人物使用同样的居中信息结构和年龄、性别标签，额外显示“形象未生成”状态与小型“创建形象”按钮。
- 人物选择弹窗宽度保留三列卡片，但高度随内容收缩，仅在人物较多时滚动，避免数据较少时出现大块底部空白。

人物卡只展示决策所需信息：

- 当前形象或默认头像
- 中文名 / 英文名
- 年龄 / 性别
- 编辑入口

由于基础资料保存前已经强校验，本阶段不显示“缺英文名、缺年龄、缺外貌”等资料缺失标签。

人物一旦被选入课程就必须存在可用当前形象；前端禁止选择，服务端保存时再次校验。课程人物卡不展示“未创建形象 / 已创建形象”等状态描述。

## 难度与知识点顺序

- 难度顺序固定为 `Starter → A1 → A2 → B1 → B2 → C1 → C2`。
- Starter 的课程总词数预算按 30 / 45 / 60 分钟分别为 160 / 240 / 320 词，并进入数据库枚举、API 校验、教学规划策略和 AI 上下文。
- 语法 seed 将“时态”放在第一组并赋予最小 `sortOrder`；预设接口按 `sortOrder`、`label` 返回，语法库和 Step1 沿用接口顺序。
- 原“时态与体”不是文字截断；“体”指进行、完成等动作状态。教师界面统一简化为“时态”，migration 同步更新既有测试数据。
- 已选知识点使用有边界的浅品牌色标签，避免纯白标签与页面背景重合。

## 文案原则

- 用户可见文案只保留任务、选择、状态、错误和恢复动作。
- 不向用户解释“硬约束”“数据真相源”“下游内容”“AI 费用”等内部概念，除非当前操作会产生不可忽略的业务后果。
- 不用说明文字弥补交互不清晰；优先通过分组、按钮标签、禁用原因和选中态降低理解成本。
- 底部操作区只显示当前第一阻断原因或已完成摘要。
- 下游重置、图片生成计费和保存失败属于必须反馈的信息，需要明确但短。

## 就地编辑

- 点击编辑打开居中弹窗，基础资料与人物形象在同一个界面维护。
- 保存后刷新当前选择中的人物展示。
- 人物形象默认提供照片上传，描述生成作为次选入口；详细外貌设置按需展开。
- 图片生成必须由用户明确点击触发，并在操作前显示会产生一次生成。
- 图片生成失败不影响课程表单和人物基础资料。

## 课程人物快照

课程不能长期直接读取会变化的人物档案作为生成真相源。

保存授课对象时，`CoursePerson` 同时保存：

- `personId`
- 课程角色：老师 / 学生
- 中文名快照
- 英文名快照
- 年龄快照
- 性别快照
- 当前人物形象资产 ID 快照，可为空

结果：

- 人物档案后续修改不会暗中改变已创建课程。
- 在授课对象页重新保存时，课程明确刷新为人物档案最新资料。
- 已发布课程始终可追溯当时使用的人物信息和形象版本。

## 初始状态与按钮

初始状态：

- 课程名称为空。
- 未选择老师。
- 未选择学生。
- 时长默认选择 60 分钟。
- 未选择英语难度。
- 未选择知识点。
- 下一步禁用。

下一步启用条件：

- 课程名称去除首尾空格后非空。
- 恰好 1 位启用老师。
- 至少 1 位启用学生。
- 时长为 30、45 或 60。
- 英语难度为 Starter-C2。
- 至少选择 1 个有效知识点。

禁用时只展示第一个未完成原因：填写课程名称、添加老师、添加学生、选择时长、选择英语难度或选择知识点。

底部首个未完成原因使用错误色显示，帮助教师快速定位缺失信息；信息完整后恢复中性保存状态。

## API 合同

### `POST /api/courses`

原子创建课程和人物快照。

请求必须携带 `Idempotency-Key`。同一账号和相同 key 重试时返回第一次创建的课程，不重复创建草稿。

```ts
type CourseAudienceInput = {
  title: string;
  teacherId: string;
  studentIds: string[];
  durationMinutes: 30 | 45 | 60;
  englishLevel: "Starter" | "A1" | "A2" | "B1" | "B2" | "C1" | "C2";
  knowledgePointIds: string[];
};
```

响应：

```ts
{
  course: {
    id: string;
    lifecycleStatus: "draft";
    currentStage: "story_outline";
  };
}
```

失败：

- `400` 课程信息不完整。
- `404` 人物不存在。
- `409` 人物不可用或角色不匹配。
- `500` 课程创建失败。

创建失败时不留下半完成课程，前端保留全部表单内容。

### `GET /api/courses/:id/audience`

读取课程管理名称、时长、课程人物快照及当前人物档案摘要。

历史快照和当前档案有变化时，响应返回 `profileChanged = true`，但不自动覆盖课程快照。

### `PUT /api/courses/:id/audience`

更新授课对象并刷新人物快照。请求同 `CourseAudienceInput`。

如果故事大纲尚不存在，直接在事务中更新。

如果已存在下游内容：

- 只修改课程名称：直接保存，不影响下游。
- 修改老师、学生、时长、英语难度或知识点：返回 `409`，要求确认重置。
- 请求带 `resetDownstream = true` 后，在单个事务中更新授课对象、刷新快照并删除故事大纲、教学规划、文案练习、视觉资源和预览发布设置；事务提交后清理对应本地图片。任一步数据库写入失败时保留原课程状态。
- 不物理删除已成功图片。

事务失败时课程和全部下游内容保持原状。

## 数据结构

课程状态直接由当前阶段和各模块确认状态表达，不增加并行工作流模式字段。

```ts
type Course = {
  id: string;
  title: string;
  durationMinutes: 30 | 45 | 60;
  englishLevel: "Starter" | "A1" | "A2" | "B1" | "B2" | "C1" | "C2";
  knowledgePointIds: string[];
  lifecycleStatus: "draft" | "published" | "archived";
  currentStage:
    | "audience"
    | "story_outline"
    | "teaching_plan"
    | "content"
    | "visual_resources"
    | "preview";
  createdAt: Date;
  updatedAt: Date;
};

type CoursePerson = {
  id: string;
  courseId: string;
  personId: string;
  role: "teacher" | "student";
  chineseNameSnapshot: string;
  englishNameSnapshot: string;
  ageSnapshot: number;
  genderSnapshot: "male" | "female";
  visualAssetIdSnapshot: string | null;
  createdAt: Date;
  updatedAt: Date;
};
```

约束：

- 一个课程恰好一个老师关联。
- 一个课程至少一个学生关联。
- 同一人物不能在同一课程中重复关联。
- 英语难度和全课知识点保存在 `Course`，是 Step 2 推荐和 Step 3 教学规划的唯一上游真相源。
- `knowledgePointIds` 必须全部对应当前启用的知识点；后续章节只能从这组知识点中选择。

## 状态与失败恢复

- 新建页未提交前不创建数据库记录。
- 创建成功后 `currentStage = story_outline`。
- 更新失败不创建新课程，不改变旧快照。
- 人物编辑失败时抽屉保留输入，课程选择保持原状。
- 人物形象生成失败不影响基础资料或课程保存。
- 修改老师、学生、时长、英语难度或知识点且存在后续成果时，使用项目内弹窗动态列出影响范围。用户可以保留后续成果并暂不应用本次修改，也可以应用修改并清理后续成果；不得使用浏览器原生确认框或强制删除。
- 页面重复提交使用 `Idempotency-Key` 幂等保护，避免创建两门相同草稿课程。

## 验收标准

- `/courses/new` 直接进入可填写的基础信息页面。
- 阶段一用户可见名称为“基础信息”。
- 阶段一出现课程名称、老师、学生、课程时长、英语难度和全课知识点。
- 页面不出现内部开发说明、数据结构说明或冗余流程解释。
- 页面通过视觉分组、选中态、禁用原因和操作按钮引导用户完成填写。
- 人物通过搜索弹层选择，不铺开全部人物。
- 基础资料完整，因此不显示资料缺失标签。
- 无可用当前形象的人物可以查看资料和就地完善形象，但不能选入课程。
- 可以在当前页面通过同一个编辑弹窗维护人物资料和人物形象。
- 保存课程时写入人物快照。
- 人物档案后续变化不自动改变已有课程。
- 至少选择 1 个知识点；超过 10 个只提示教学密度风险，不阻断保存。
- 语法库可以按类别切换后选择知识点，切换类别不清空已选项。
- 修改名称不重置下游；修改老师、学生、时长、英语难度或知识点时由用户选择“保留后续成果，暂不应用”或“应用修改并清理以上内容”。保留时停留当前页且不写入这次上游修改，避免新旧课程约束同时生效。
- 阶段一保存不自动产生 AI 费用。
- 代码、API 和数据使用唯一的正式命名，不保留版本兼容分支。
