# 课程创建阶段五：视觉资源

## 模块目标

阶段五基于 Step 2 已确认角色和 Step 4 clean reading，完成本课视觉定型、角色查看、封面校准和章节图片生成。

本阶段不修改故事、正文、练习或答案。图片、参考图和图片版本统一由 `course_images` 管理。

## 设计原则

- 默认流程只解释老师当前要完成的任务，不暴露 provider、JSON 或 Prompt 技术细节。
- 视觉方案是明确阶段；页面加载不自动产生图片费用。
- 一门课程只生成一份统一角色形象，不为每章分别生成服装设定。
- 参考图只锁定身份外貌，本课服装、道具、动作和场景由视觉方案决定。
- 视觉方案、封面和章节图片都只在老师点击后生成；角色区不增加确认步骤，封面确认后才允许生成章节图片。
- 封面确认后允许按任意章节顺序生成。
- 成功图片、上传参考和历史版本不因修改或失败被删除。
- Prompt 只读、默认折叠，仅用于排查问题。
- 图片不得把具名角色的头部、脸部或身体裁在画布边缘之外。
- 高级模式只收纳低频课程级控制，不隐藏正常图片编辑、重生成和历史版本。

## 输入边界

视觉方案只读取最小必要输入：

```ts
type VisualPlanInput = {
  storyTitle: string;
  characters: Array<{
    id: string;
    displayName: string;
    englishName: string;
    sourceType: "person" | "referenced" | "original";
    roleInStory: string;
    reference: {
      name: string;
      type: CourseSourceReferenceType;
      summary?: string;
    } | null;
  }>;
  chapters: Array<{
    id: string;
    order: number;
    title: string;
    paragraphs: Array<{ id: string; cleanReading: string }>;
  }>;
};
```

不得读取英语等级作为视觉语义、教学规划、Step 2 重复大纲或中间消息、学生版挖空文本、练习和答案。

Step 2 是角色身份真相源；Step 4 clean reading 是最终场景语义真相源。Step 5 不新增具名角色。路人、群众和普通环境动物可以作为非固定背景元素，不进入角色确认。

## 视觉定型方案

视觉方案一次输出全课画风、角色定型、封面和逐段图片槽：

```ts
type CourseVisualBible = {
  schemaVersion: 4;
  revision: number;
  mode: "faithful" | "originalized";
  visualStyle: string;
  storyWorld: string;
  characterDesigns: Array<{
    characterId: string;
    visualAnchor: {
      mode: "reference" | "semantic" | "description";
      label: string;
      context: string | null;
    };
    appearanceDescription?: string | null;
    courseAppearance: string;
  }>;
  mainCharacterIds: string[];
  cover: {
    focus: string;
    characterIds: string[];
    sceneDescription: string;
  };
  shots: Array<{
    paragraphId: string;
    focus: string;
    characterIds: string[];
    sceneDescription: string;
  }>;
};
```

上面是服务端最终存储结构，不是 AI 直接返回协议。AI 输入和输出只使用本次请求内稳定的短 key：角色为 `C01 / C02 / ...`，段落为 `P01 / P02 / ...`；数据库 `characterId` 和 `paragraphId` 永不交给 AI 复制。角色中文名和英文名来自 Step 2。视觉方案只返回中文 `characterAppearance`、`courseAppearance` 两类角色设定，不再维护对应英文镜像字段；英文 `Scene`、`Focus`、`visualStyle` 和 `storyWorld` 继续由 AI 生成。

约束：

- 老师、学生使用 `reference`，不由文本 AI 复述或编造外貌。
- 图片模型大概率认识的命名对象使用 `semantic`，保留准确英文名和人物/作品/版本上下文；中文 `appearanceDescription` 仍作为老师可编辑的可见外貌真相源。
- 原创角色、原创化角色，以及没有可靠内置视觉形象的文字角色使用 `description`，由中文 `appearanceDescription` 提供一段简短稳定描述。
- 老师为任意引用角色上传原作参考后，运行时直接以参考图优先，不要求重新生成视觉方案。
- `courseAppearance` 是唯一的中文本课造型字段，只允许服装、鞋和随身道具，不允许身份、年龄、脸、体型、性格、表情、动作、姿势、视线、能力、环境或场景指令。它必须是一份可复现的全身固定造型：明确上装、下装、外层、鞋的品类与主辅颜色，并在视觉上有意义时写明材质、纹样及随身道具或配饰的颜色；不得使用“经典造型”“时代服装”“相近颜色”等模糊占位描述。
- `appearanceDescription` 是课程角色唯一的中文稳定外貌字段；人物档案角色不生成该字段，身份外貌只来自人物档案参考图。
- 不保存 `stableAppearance`、`courseClothingAndProps`、`courseAppearanceDescription` 或人工 `additionalAppearance` 等中英文镜像和叠加字段，防止老师修改后出现两份真相源。
- 老师学生的本课造型必须根据故事标题、全部 clean reading 和 AI 同次生成的 `storyWorld` 设计。历史、奇幻、文学作品或 IP 世界中的课堂人物要采用适龄、便于行动且与故事世界协调的服装和道具；不得默认给老师现代教师装、给学生通用运动装。
- 忠实还原的引用角色默认沿用经典造型，但仍须在 `courseAppearance` 中把可见服装部件和准确配色具体复述出来；除非故事明确要求，不用本课服装覆盖其标志性设计。
- 同一份 `courseAppearance` 对封面和全部章节图片都是不可变的连续性规格，场景不得自行遗漏、改色或改款。clean reading 明确发生换装时，才把发生变化的单品写入对应 `sceneDescription`，其余造型保持不变，不增加逐章服装模型。
- 人物档案角色的外貌不由文本 AI 编造，生图时读取当前课程人物快照参考图。
- 年龄、时代服装、换装和变身等正文明确变化直接进入对应 `sceneDescription`，不增加跨章节人物状态模型。
- `shots` 必须逐段覆盖 clean reading，并只使用 Step 2 已存在的角色 ID。
- 视觉方案不生成练习图片、答案图片或包含可读文字的图片。

## 角色分层

AI 输出每张图的角色短 key，服务端映射为角色 ID 后再根据确定性事实计算主要角色：

1. 老师和学生属于身份角色，始终进入需要确认的范围。
2. 出现在封面的角色优先。
3. 主角、关键对手和推动主线的角色优先。
4. 在更多图片槽中重复出现的角色优先。

默认选出最多 2–3 个主要课程角色；老师和学生不计入该数量上限。Step5 角色区按“老师学生 / 主要角色 / 其他角色”三个子 Tab 展示，不要求逐角色或整体确认。

实际视觉角色集合取封面和全部图片槽 `characterIds` 的并集，不直接等同于 Step 2 的全部角色数。

## 人物外貌与本课造型

人物档案图和老师上传图必须锁定：

- 体型和身高感。
- 脸型、五官结构和比例。
- 发型、发色。
- 眼镜、胡须、痣等可辨识特征。
- 年龄感和肤色。

参考图不得锁定服装、鞋帽、道具、姿势、表情、背景、光线、摄影风格和构图。

本课服装和道具由 `courseAppearance` 统一确定。老师更换参考图后不重新生成视觉方案，只重新编译受影响图片的最终 Prompt，并把相关成功图片标记为过期。

## 图片生成时的动态编译

图片模型只读取当前图片需要的信息：

```ts
type ImageGenerationInput = {
  visualStyle: string;
  storyWorld: string;
  sceneDescription: string;
  focus: string;
  characters: Array<{
    characterId: string;
    characterKey: string;
    chineseName: string;
    englishName: string;
    visualAnchor: {
      mode: "reference" | "semantic" | "description";
      label: string;
      context?: string;
    };
    appearanceDescription?: string;
    courseAppearance: string;
    referenceAssetId?: string;
  }>;
  referenceImages: string[];
};
```

运行时规则：

- 有人物档案图或上传参考图时，附带当前参考资产，并明确只参考身份外貌。
- `semantic` 角色没有参考图时，只注入准确名称、人物/作品/版本上下文和必要区分提示，优先使用图片模型已有知识。
- 每张图都注入出场角色的同一份 `courseAppearance`，并明确要求封面和全部章节保持服装品类、颜色、材质、纹样、鞋和随身道具一致；只有场景明确写出换装时才能改变指定单品。
- `description` 角色没有参考图时，同时注入中文 `appearanceDescription`。
- 同一画面允许混合图片参考角色、文字参考角色和原创角色。
- 多张参考图按稳定顺序合成，并在 Prompt 中明确参考顺序与角色 ID 的映射。
- 不向单张图片传入其他段落或不出场角色。
- `CourseImage.prompt` 记录该版本真正提交的不可变 Prompt；页面查看的是按当前方案和参考资产即时编译的只读预览。预览和实际提交必须共用同一套角色视觉名称、参考图映射及编译参数；原创化角色不得在页面预览中重新显示原作名称。

最终 Prompt 只保留 16:9 横版儿童绘本、全课画风和世界、当前角色与参考图映射、当前场景与重点、完整入画、无文字和水印等有效约束。删除重复课程信息、未出场角色、重复风格描述、逐场景完整角色复述和 provider 说明。

多人 IP 仍按独立角色生成视觉定义和角色 ID。生图时只注入当前图片实际出场成员；UI 可以按共同作品来源折叠展示，但不新增群像领域对象。

## 动态构图规则

- 1–4 个具名角色按场景动作与情绪自然选择景别，不强制全部使用全身远景。
- 不得在画布边缘裁掉具名角色的头部或脸部；动作需要时保持完整身体入画。
- 5 个及以上具名角色自动使用群像远景，全部角色保持可辨认、相互分离且完整位于画布内。
- 允许被桌子、树木等场景物体自然遮挡，但不能被画布边缘意外裁剪。
- 不使用头像拼贴、证件照、角色立绘排列或纯人物列队构图。

所有封面和正文插图持久化为 `1536×864` 的 16:9 PPT 横版画面。

## 默认用户流程

```text
手动生成视觉方案
-> 查看角色形象
-> 手动生成并确认封面
-> 生成章节图片
-> 进入预览发布
```

### 进入页面

页面顶部保留 Step5 标题、必要操作和一张紧凑的“图片生成流程”状态卡，明确显示“视觉方案 / 主要角色 / 视觉封面 / 章节图片”四段进度。“主要角色”是查看与调整阶段，不恢复已取消的确认门禁。

流程卡下方保留独立“视觉方案”组件：未生成时提供“生成视觉方案”，已生成时显示封面、章节与图片数量并提供“更新视觉方案”。更新会替换角色设定、封面方案和章节图片方案，使当前采用图片等待重新生成，因此首次点击只打开应用内确认框；老师确认后才调用 AI。上传参考图和历史图片版本继续保留。

视觉方案请求进行中时，组件必须展示“正在生成视觉方案”、真实已等待时间和诚实的耗时预期：通常需要 1–3 分钟，角色或章节较多时可能更久。不得伪造百分比或虚构后台阶段，并明确说明系统仍在处理、无需重复点击。生成完成后不只显示一行状态，改用成果展示框分别汇总角色数量、封面方案和章节图片方案，并给出下一步“检查角色形象并生成视觉封面”。

所有模块标题沿用 Step1 组件样式：浅色标题栏、深色标题文字、紧凑内边距。页面内容宽度与 Step1 一致使用 `max-w-5xl`，不在模块内部重复增加大面积左右空白。

首次主要操作为“生成视觉资源方案”。生成方案不自动提交图片任务。

AI 返回视觉方案后，服务端先持久化视觉设定和图片槽。此时人物参考资产可以尚未装载，槽位 Prompt 使用明确的待注入参考占位；真正提交图片生成时再读取并严格校验当前参考图、建立稳定编号映射。不得因为方案落库阶段暂时没有参考图而把已成功返回的视觉方案报成 500。

视觉方案属于结构化规划任务，GPT 请求固定使用低推理强度，并在 Prompt 中限制各字段的实际长度；不设置可能同时截断推理与可见 JSON 的硬输出上限。解析前只删除无害额外字段、补齐明确声明为可空的创意字段并裁剪超过契约上限的描述。AI 必须逐一返回全部 `Cxx` 角色和 `Pxx` 段落；遗漏、重复或未知短 key 均严格失败，并记录具体字段位置、错误值和允许值，不生成默认兜底、不静默删除或补齐。供应商明确返回输出未完成、JSON 截断或结构不完整时，接口返回 `invalid_ai_response` 和 `retrySafe: true`，界面提示重新生成但不得误报为网络中断。失败提示必须保留到老师主动关闭或开始下一次操作，页面重新聚焦和后台同步不得自动清除。

### 视觉方案生成后

页面直接展示角色区、视觉封面和章节图片，不出现“确认主要角色”操作。封面和章节图片仍由老师分别手动触发。

### 角色卡片

“主要角色”模块说明固定为：“系统将根据故事生成角色形象；若封面生成的人物形象不够精确，可上传参考图后重试。”

- 老师学生卡展示中文名、英文名、人物档案形象和 AI 返回的中文“本课形象”；没有图片时使用人物档案同款首字头像，不允许在 Step5 上传参考图。
- 课程角色卡展示中英文名、AI 返回的中文角色外貌、本课造型和当前参考图；没有参考图时使用首字头像。不得用“沿用经典角色形象”等前端固定占位句冒充 AI 结果。
- 只有课程角色允许选择、拖入或通过 `Ctrl + V` 粘贴参考图；上传成功后卡片立即以参考图替换首字头像。
- 高级模式在卡片上提供编辑入口，通过紧凑弹窗修改：老师学生只改中文“本课造型”；课程角色可同时修改中文“角色形象”和“本课造型”。有参考图时参考图身份优先，文字负责可见特征、服装和道具。
- 保存角色设定后保留当前采用图片、封面确认和全部历史版本；受影响的封面或章节图片卡使用弱提示“角色设定已更新，现有图片不会自动变化；如有需要，请重新生成。”，角色卡自身不显示图片同步提示。判定只比较图片真正使用的角色外貌与本课造型，不因中英文名或 Prompt 模板调整误报。是否重新生成由老师按需判断。
- 二级角色 Tab 使用紧凑分段控件，不使用与模块标题栏相似的大面积标题样式，也不保留长下划线和多余垂直间距。
- 卡片参考人物档案：左侧固定 `96×144` 形象，右侧名称和描述整体居中；两列卡片铺满可用列宽，不为单张卡片额外增加左右留白。
- 每个角色分类每页最多显示 6 张卡片；超过后显示上一页、页码和下一页，不提供搜索。切换分类时回到第一页。

### 封面确认

视觉方案生成后即可手动生成封面，不依赖角色确认。封面区只展示一张 16:9 图片工作区，不增加问题分类。

封面支持生成、确认并开放章节生成、上传参考后重新生成、聊天修改、重新生成成功图片，以及查看和切换历史版本。

普通模式提示：

> 如果主要角色形象不准确，可以在上方角色区域上传参考图，然后重新生成封面。

上传参考图不重新生成视觉方案。新封面成功后保留旧版本，老师需要再次确认当前封面。

### 章节图片

封面未确认时，章节 Tab 可以浏览 clean reading 和待生成图片槽，但付费章节生成按钮禁用，并说明“请先确认视觉封面”。

封面确认后自动定位到第一个未完成章节。老师可以跳转到任意章节并按任意顺序生成，支持生成当前章缺失图片、生成单张和生成全部缺失图片。

## 封面与多章节 Tab

视觉方案生成前不展示空封面与章节模块。视觉方案生成后，封面和章节使用两个独立模块；章节模块内部使用章节 Tab。

### 状态汇总

至少显示封面状态、章节总数、图片总数、已完成、生成中、失败和待生成数量。状态只使用业务语言，失败和生成中不能只依赖颜色表达。

### Tab 导航

章节 Tab 顺序固定为：

```text
第 1 章 | 第 2 章 | ... | 第 N 章
```

每个章节 Tab 显示“待生成”“生成中”“x/y 已完成”“生成失败”或“已完成”。

章节较多时：

- Tab 单行横向滚动，不换成多行按钮墙。
- 当前 Tab 自动滚入可视区域。
- 同时提供“跳转章节”入口，列出章节标题和状态。
- 支持键盘左右方向键切换，并保留清晰焦点状态。

### 章节 Tab 内容

每个章节顶部展示章节序号与标题、本章完成状态、“生成本章缺失图片”和“跳转到下一个未完成章节”。

每个段落图片槽只展示 clean reading 正文、16:9 图片或占位区、状态和当前可用操作。默认沿用现有双列图片卡；宽度不足时退回单列，不嵌套多层同权重卡片。

## 默认模式与高级模式

默认模式始终提供：

- 生成和确认视觉方案。
- 上传或更换原作角色参考图。
- 生成、确认和重新生成封面。
- 按全部、章节或单张生成图片。
- 聊天修改单张图片。
- 重新生成成功图片。
- 查看和切换历史版本。
- 重试失败图片。

高级模式收纳：

- 调整全课视觉方案。
- 调整画面质量。
- 改用原创视觉设定。
- 修改老师学生的本课形象。
- 修改课程角色的角色形象和本课造型。

画面质量按实际请求模型解析：`gpt-image-2-c` 按图片张数固定收费，因此无论课程当前选择、生成或编辑、主模型或 429 兜底、课程图片或人物形象，实际请求一律使用 `high`。其他模型继续使用老师选择的质量。图片版本保存实际提交的质量；存储失败后恢复也不得丢失该实际质量。

当前视觉方案包含引用角色时，高级设置始终提供原创视觉设定入口：`faithful` 方案显示“改用原创视觉设定”，`originalized` 方案显示“重新调整原创视觉设定”。不要求老师先消耗一次失败的图片生成；检测到 `policy_blocked` 时，页面顶部同时说明老师既可以在图片卡直接重试，也可以主动调整原创视觉设定。原创化不是强制恢复路径，执行前必须确认替换影响。

图片 Prompt 不依赖高级模式：封面和每张章节图片都在图片上方提供默认折叠的只读 Prompt，便于直接排查。

高级模式使用低强调入口，默认关闭。正常流程、封面不满意和普通失败不主动提示老师进入高级模式。

## 安全策略拦截

失败必须结构化区分：`retryable`、`storage_recoverable`、`invalid_request`、`policy_blocked` 和 `unknown`。

检测到 `policy_blocked` 后，页面顶部出现：

`部分图片受到生成限制。可以直接重试当前图片，也可以改用原创视觉设定。`

说明：

> 系统保留故事内容和整体视觉气质，将引用角色、专有地名及背景元素转换为不依赖原作名称识别的描述性视觉设定。老师也可以先直接重试当前图片。

原创化不修改 Step 2 故事和 Step 4 clean reading。文本 AI 尽可能保留原方案的构图、氛围、色彩方向、材质、时代感、人物关系和场景动作；为 `referenced` 角色生成新的视觉名称、角色形象和本课造型，并把专有地名、作品背景、标志性建筑、符号及依赖原作识别的视觉组合转换为能够独立成立的文字描述。广义角色原型和相近情绪印象可以保留，不要求机械修改固定数量的视觉维度。

服务端采用 AI 返回的描述性 `visualStyle` 和 `storyWorld`，同时强制保留人物档案角色、已有原创角色及各场景出场关系。新 revision 停用引用角色原有 IP 参考图，最终图片 Prompt 只使用新视觉名称；旧参考图和历史图片版本不删除。原创化后清空当前封面与章节图片采用状态并取消封面确认，但不自动生成新图片。已经处于 `originalized` 的方案仍可再次调整，以修复残留的专有背景或视觉锚点。

批量生成遇到第一个确定性策略拦截后，暂停相同角色组尚未提交的图片，避免继续产生无效请求。

## 图片版本与失败恢复

- 每次成功生成自动成为当前采用版本，失败不改变当前采用版本。
- 成功版本不可覆盖；老师可从任意成功版本继续修改或切换历史版本。
- 封面、单张插图、章节批量和全部批量生成期间，loading 直接填充对应的 16:9 图片框，展示当前操作、真实已等待时间和“通常需要 1–3 分钟”的预期；生成完成后在原位展示图片，不额外增加独立状态卡，不伪造进度，也不要求老师反复点击。
- 图片修改框先提示老师明确描述修改对象、位置和目标结果，并用“消除画面右侧重复的角色，其他人物和构图保持不变”作为输入示例。服务端只把当前原图和本次修改诉求交给图片编辑模型；修改 Prompt 将诉求置于最高优先级，要求保留未被点名的内容，不再混入完整旧 Prompt 或其他角色参考图。
- 重试或编辑一旦产生新版本，图片卡自动切换到该最新任务；任务成功并被服务端采用后立即展示新图，不依赖整页刷新。老师主动查看历史图时仅在服务端版本状态未变化期间保留选择。
- 生成或编辑失败时，当前方案最新一次失败及服务端原因显示在对应图片卡内；开始重新生成、图片编辑、更新视觉方案或原创化后，立即隐藏上一次错误并展示新任务状态。新操作成功后，旧失败版本继续保留用于审计，但不再参与图片卡、章节 Tab、失败数量或策略拦截状态。编辑失败可回到父版本修改要求后重试。
- 若同一幂等请求已经生成成功但采用关系因响应或落库中断而丢失，服务端优先修复当前采用关系并返回既有图片，不再次调用图片模型。
- 更换参考或视觉方案 revision 后，只把受影响图片标记为过期。
- 图片服务返回远端 URL 后，必须先把 URL 写入当前图片任务，再开始下载和本地持久化；即使随后连接超时或写入失败，也不会丢失已经付费生成的结果。
- `storage_recoverable` 失败在图片卡显示“重新保存图片”。重试必须领取并续跑同一条图片任务，只下载既有远端 URL，不新建版本、不再次调用图片生成或编辑模型。
- 服务端下载第三方图片固定使用 IPv4，避免部署节点存在不可达 IPv6 路由时 Node 按 DNS 顺序持续等待；对连接超时、`408`、`429` 和 `5xx` 进行有限重试，并限制重定向次数、文件大小和单次等待时间。
- 页面刷新后恢复视觉方案确认、封面确认、Tab 状态和图片版本。
- 成功且输入指纹未变化的图片直接复用。
- 所有付费写操作使用 `Idempotency-Key`。视觉方案生成在调用 AI 前以该 key 创建 `AiGenerationLog` 账本记录；相同 key 处于执行中、已失败或已成功时都不得再次调用 AI。AI 原始响应和 token 用量必须先于结构与业务校验写入账本，随后再保存解析诊断和最终状态；解析失败至少记录错误类别、响应字符数、JSON 是否闭合以及具体 schema 或语义规则。AI 已成功返回但后续校验或数据库写入失败时，原始响应或解析后的方案留在账本中，能够离线排查；已有解析方案时相同 key 可以继续落库而不重新消费 AI。角色或段落短 key 遗漏、未知或重复时严格失败，不自动发起 AI 修复，也不生成默认方案。

### 生成任务状态机

```text
pending
  -> generating（领取租约，attempt + 1）
  -> succeeded（持久化成功并自动采用）
  -> failed（保留失败码和可恢复的远端结果）

generating --租约过期--> failed / retryable --老师重试--> generating
```

- 图片任务使用两分钟服务端租约，运行中的请求每 30 秒续租；进程退出、部署重启或任务异常中断后，租约不会被续期。单次尝试另设 12 分钟硬上限，即使底层请求没有正确结束也会交还重试权。
- `GET /visual-resources` 会回收过期的 `pending / submitting / generating`，统一转为可重试失败，不让刷新后的页面永久停在“生成中”。没有租约的历史任务以 15 分钟无更新作为兼容回收线。
- 同一图片槽、同一视觉方案 revision 在数据库中最多存在一个活跃生成任务；不同浏览器 Tab 同时点击也不会调用两次图片模型。
- 图片成功、失败和租约续期都必须携带本次 `leaseToken`；旧请求超时返回时不能覆盖新重试的结果。
- 图片接口响应丢失、网关超时或返回体中断属于“结果未知”，前端先调用 GET 对账。若服务端已经出现新版本或状态变化，继续轮询而不自动重提付费请求；若状态未变化，提示恢复网络后安全重试。
- 图片 POST 尚未返回时也每 3 秒同步一次。浏览器恢复联网、标签页重新可见时立即同步；Step 5 内切换封面/章节 Tab 不停止任务或轮询。
- 章节或全部图片批量生成时，批次状态只锁定批量操作；每张卡片按自己的服务端版本状态渲染。已成功图片立即展示，当前任务显示“生成中”，尚未领取任务的图片显示“等待生成”，不得用批次级 Loading 遮住已成功图片。
- 当前视觉方案只统计同 revision 的活跃任务；旧方案残留状态不阻断新方案生成、预览或发布。
- 预览和发布只阻断仍持有有效租约的任务。过期任务即使尚未被 GET 写回，也不能永久锁死课程流程。

## API 边界

视觉资源 API 位于 `/api/courses/:id/visual-resources/...`。

### `GET /api/courses/:id/visual-resources`

返回视觉方案、revision、角色分组所需信息、封面确认、课程与章节汇总、图片槽和版本历史。GET 不创建付费任务。

### `POST /api/courses/:id/visual-resources/plan/generate`

基于最小输入生成或重新生成视觉方案和全部图片槽，不提交图片任务。新方案产生新 revision；旧图片保留并按依赖标记过期。

### `PATCH /api/courses/:id/visual-resources/characters/:characterId/appearance`

老师学生仅接受 `{ courseAppearance }`；课程角色接受 `{ appearanceDescription, courseAppearance }`。字段均为中文。保存后不清空当前图片和封面确认；GET 只比较受影响图片实际 Prompt 中的角色外貌与本课造型，在对应封面或章节图片槽返回 `hasUnsyncedChanges`。

### `POST /api/courses/:id/visual-resources/cover/confirm`

请求 `{ assetId: string }`，确认当前 revision 的封面成功版本。只有确认封面仍有效时才允许生成章节图片。

### `POST /api/courses/:id/visual-resources/plan/originalize`

对当前方案中的 `referenced` 角色生成不依赖原作名称识别的描述性视觉设定，并转换专有地名和背景元素；尽可能保留整体视觉语言、构图、氛围和故事动作，强制保留人物档案角色、已有原创角色和出场关系。`faithful` 与 `originalized` 方案都可调用，产生新的 `originalized` revision，不自动生成图片。

### `POST /api/courses/:id/visual-resources/characters/:characterId/reference`

上传并保存角色外形参考，只做校验、归一化和持久化，不调用图片模型。

### `POST /api/courses/:id/visual-resources/characters/:characterId/use-latest-person-visual`

采用人物档案最新形象，只更新本课程参考并把受影响图片标记为过期。

### `PATCH /api/courses/:id/visual-resources/settings`

高级模式更新后续生成质量，不改变已有图片状态。

### `POST /api/courses/:id/visual-resources/images/generate`

请求：

```ts
{
  scope: "cover" | "slot" | "chapter" | "all";
  slotId?: string;
  chapterId?: string;
}
```

服务端运行时动态编译 Prompt。封面不要求角色确认；章节范围要求当前封面已确认。批量只生成缺失图片。

### 图片版本接口

- `POST /assets/:assetId/refine`：基于成功版本和一句修改要求生成子版本。
- `POST /assets/:assetId/select`：采用指定成功版本；切换封面后需要重新确认。
- 普通失败和 `policy_blocked` 都可以由老师通过 `POST /images/generate` 对目标槽手动重试；系统不自动重提付费请求，也不强制切换原创方案。策略拦截时同时提供原创视觉设定作为可选恢复路径。
- 更换参考图或视觉方案后清空受影响槽的当前采用关系，但历史成功版本继续保留。

## 数据结构

视觉方案需要持久化：

```ts
type CourseVisualResourcePlanState = {
  revision: number;
  mode: "faithful" | "originalized";
  bible: CourseVisualBible;
  confirmedCoverAssetId: string | null;
};
```

图片槽保存稳定语义，不把预编译 Prompt 当作真相源：

```ts
type CourseVisualImageSlot = {
  id: string;
  courseId: string;
  slotType: "visual_cover" | "lesson_shot";
  chapterId?: string;
  paragraphId?: string;
  sourceText: string;
  characterIds: string[];
  focus: string;
  sceneDescription: string;
  activeAssetId: string | null;
};
```

图片版本新增 `planRevision` 和结构化 `failureCode`，并记录真正提交的 `prompt`、参考资产、质量和 source hash。生产字段变更必须通过 Prisma migration；生产环境只执行 `pnpm prisma:deploy`。

## 与预览发布的边界

阶段五不生成课件页面，不修改正文和练习。没有图片时仍可使用占位进入预览发布；存在生成中任务时，前后端同时阻断进入预览和发布。图片失败不阻断老师使用占位继续。

## 验收标准

- 视觉方案只读取 Step 2 角色和 Step 4 clean reading 等最小必要输入。
- 不为每章生成服装设定。
- 主要角色由服务端根据封面、故事作用和出场次数计算。
- 视觉方案生成后才展示封面与章节 Tab。
- 视觉方案生成后即可手动生成封面，不需要确认角色；封面确认后才能生成章节图片。
- 封面未确认时可以浏览章节正文和占位，但不能提交章节图片任务。
- 多章节使用单行可滚动 Tab、状态汇总和章节跳转入口。
- 封面确认后可以按任意顺序生成，并默认定位到第一个未完成章节。
- 默认模式保留课程角色参考图上传、聊天修改、成功图重生成和历史版本；老师学生不在 Step5 上传参考图。
- 页面保留紧凑流程状态卡和独立视觉方案组件；所有模块标题与 Step1 保持一致，主体宽度为 `max-w-5xl`。
- 流程状态固定为四步：视觉方案、主要角色、视觉封面、章节图片；更新既有视觉方案必须二次确认后才发起 AI 请求。
- 新生成方案必须为老师学生返回中文本课形象，为课程角色返回中文稳定外貌；人工补充为空时不展示，旧方案缺字段时明确提示更新方案。
- 老师学生本课造型必须与故事世界匹配；角色卡文字居中、两列紧凑铺满，每个分类 6 张一页且无搜索。
- Prompt 默认折叠、只读，并按当前方案和参考资产动态编译。
- 最终角色定义使用 `Cxx + 中文名 + 英文名`，Scene 保持完整自然英文且不出现内部角色键。封面和章节插图使用不同 Prompt 模板；封面不预留标题留白。1–4 个角色按场景自然构图，5 个及以上角色自动切换为远景群像并保证角色可辨认。
- 人物参考只锁定身份特征，不锁定服装、姿势和背景。
- 所有具名角色完整入画，不出现头部、脸部或半个身体被边缘裁断。
- 策略拦截同时保留图片卡手动重试和原创视觉设定恢复入口，不自动重试、不强制原创化。
- 图片仍由 `course_images` 管理，成功版本不可变，失败不覆盖当前版本。
