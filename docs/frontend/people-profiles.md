# 人物档案模块契约

## 模块目标

人物档案维护课程会引用的老师和学生身份，并为课程插图提供可复用的当前人物形象。

人物基础信息和人物形象在同一个新增 / 编辑界面完成。界面不解释内部状态，只保留老师当前需要的操作。

## 页面入口

- 路由：`/people`
- 导航名称：`人物档案`
- 默认 Tab：学生
- 支持学生 / 老师 Tab 和搜索

“人物档案”不是组织架构或账号权限模块。本期不处理部门、职位、登录账号绑定或多教师权限。

## 人物字段

老师和学生使用同一套必填标准。

必填：

- 类型：`teacher | student`
- 中文名
- 英文名
- 年龄
- 性别：`male | female`

选填：

- 备注

删除字段：

- 兴趣爱好
- 学习目标
- 自由文本 `appearance`

外貌不再保存在人物表的长文本字段中。文生图选择、额外要求、微调指令和生成图片统一由人物形象资产管理，避免人物表和图片资产出现两个外貌真相源。

## 校验

- 中文名、英文名去除首尾空格后不能为空。
- 不限制姓名字符集，不以正则误伤中英文混合姓名。
- 年龄必须是 `1-120` 的整数。
- 性别必须明确选择。
- 类型在创建后不可修改。
- 保存失败时编辑界面保留全部输入。

## 人物列表

人物列表展示：

- 学生使用姓名首字头像，不使用人物形象图片
- 老师有当前形象时使用当前形象，否则使用姓名首字头像
- 中文名 / 英文名
- 年龄 / 性别
- 备注摘要
- “编辑”入口

“编辑”使用白底描边按钮，包含铅笔图标和文字；不得使用与卡片背景融为一体的幽灵按钮。悬停时增强主色边框和浅色背景，但不与“新增”主按钮争夺层级。

## 新增与编辑

- 新增和编辑使用居中宽弹窗，不使用右侧抽屉。
- 弹窗使用“基础资料 / 人物形象”两个 Tab，一次只呈现一个任务。
- 编辑已有人员时默认打开“基础资料”。
- 新增人员先保存基础资料，成功后自动切换到“人物形象”；保存前人物形象 Tab 不可进入。
- 切换 Tab 不清空未保存的基础资料输入。
- 基础信息先保存，图片生成失败不得导致资料丢失。
- 编辑时不允许改变人物类型。
- 编辑时不展示人物类型入口；人物身份由“编辑学生 / 编辑老师”标题直接表达。
- 新增入口已经由人物列表当前 Tab 确定学生或老师，新增表单同样不重复展示人物类型选择。
- 课程授课对象页复用同一个编辑界面，不再提供分离的“形象工作区”入口。
- 教师端编辑界面不提供删除、停用、归档或恢复入口。
- 弹窗标题区显示人物类型图标和当前人物名称；Tab 使用统一线性图标、明确的选中背景和文字层级，不只依赖细下划线区分状态。
- “基础资料 / 人物形象”Tab 作为整体居中展示。
- 基础资料 Tab 使用一个主信息区组织必填字段和备注，字段标签、输入值、辅助信息和操作区形成明确层级；不添加无业务意义的装饰卡片。
- 基础资料不使用低信息量侧栏，人物信息以居中单栏承载；中文名、英文名、年龄、性别和备注使用不同的线性图标，并在字段聚焦时强化主色反馈。
- 新增人物的年龄输入保持空白，不使用看似默认值的数字占位符。
- 不额外展示“* 为必填项”或“修改只影响之后生成内容”等不改变当前决策的说明。
- 在窄屏和触屏设备上，表单改为单列，Tab 与主要按钮保持至少 44px 的触控区域。

### 保存反馈与首次形象引导（2026-08-20）

- 基础资料提交后，按钮立即进入“保存中”并禁止重复提交；接口失败时保留全部输入，在表单内显示失败原因。
- 编辑已有人员保存成功后自动关闭弹窗，人物列表或课程已选人物立即使用接口返回的完整最新资料，并在原页面显示“人物资料已更新”；不能让弹窗停留在原地看起来像没有生效。
- 新增人员保存成功后继续自动切换到“人物形象”，并在形象工作台顶部显示一次明确的承接提示：“人物资料已保存，下一步创建人物形象”。提示只解释当前下一步，不增加内部流程说明。
- 首次形象创建成功后提示“形象已生成”，同时保留“设为当前形象”这一独立决策；尚未设为当前形象时必须明确提示还差这一步，不能让生成成功看起来等同于课程可用。
- “设为当前形象”、删除非当前版本等有持久化结果的操作，采用“进行中按钮状态 + 成功后的可见状态变化/短成功提示 + 原位失败信息”。不为普通点击增加纯装饰动画。
- `PATCH /api/people/:id` 成功响应必须包含更新后的完整 `PersonProfile`，包括仍然有效的 `activeVisual` 和 `visualStatus`；保存基础资料不得让课程页暂时丢失人物形象。

## 人物形象

人物形象区域包含：

- 当前形象：大图展示当前正在查看的版本。
- 版本历史：按时间只展示成功版本，可切换查看；失败尝试不进入历史。
- 创作入口：上传照片生成 / 描述生成。
- 修改输入：基于当前版本输入一句修改要求。
- 明确操作：生成新版本、设为当前形象。

右侧操作区使用互斥的两状态工作台，不同时堆叠创建和修改表单：

- 首次创建态：人物没有任何形象版本时，只展示上传照片 / 描述生成。
- 结果与修改态：存在成功生成记录后，只展示当前分支的修改记录、底部修改输入和版本操作。
- 生成成功后自动进入结果与修改态。
- 生成失败时不保存人物形象资产，也不创建历史缩略图；错误在当前创建或修改入口内展示，老师可直接再次提交。
- “重新创建”是返回首次创建态的唯一入口；返回不会删除任何已有版本。

生成请求等待期间使用独立等待态，避免老师面对一个只转圈的禁用按钮：

- 首次生成和多轮修改共用同一等待反馈。
- 显示实际已等待时间，秒数使用等宽数字，避免文案跳动。
- 短等待提示请求已提交；等待变长后提示结果会自动显示；超过 90 秒明确提醒保持页面打开。
- 不显示无法验证的百分比或虚构阶段。
- 不提供无法停止上游费用的“取消生成”按钮。
- 成功后自动进入继续调整；失败后回到原输入界面，保留照片、描述或修改要求。
- 页面刷新或重新打开弹窗时，如果服务端仍有 `pending` / `submitting` 记录，前端必须恢复等待态并自动轮询 `GET /api/people/:id/visuals`，直到记录变为成功、消失或请求失败；不能要求老师再次刷新才能看到结果。
- 恢复轮询只读取服务端状态，不重新发起图片生成，不产生第二次 AI 费用。
- 轮询失败时保留当前服务端状态并显示可恢复错误，老师可以手动重试读取；不得把一次读取失败误报为图片生成失败。

每次付费操作只生成 1 张图。成功版本永不被新生成隐式覆盖；只有点击“设为当前形象”才更新人物当前形象。

人物图片 provider 读取账户高级设置，可使用 QuickRouter 或 Crazyrouter 的 `gpt-image-2`：描述生成调用图片生成接口，照片生成和后续微调调用图片编辑接口。QuickRouter 保留其专属 `gpt-image-2-c` 限流回退，Crazyrouter 只使用标准 Images API。领域层通过 provider adapter 隔离，人物资产合同不绑定第三方响应结构。

### 上传照片生成

流程：

```text
选择照片 -> 确认生成 -> 生成竖版全身人物形象 -> 设为当前形象
```

规则：

- 支持 JPG、PNG、WebP。
- 单文件最大 10 MB。
- 支持文件选择、拖放以及从剪贴板直接粘贴图片；粘贴非图片内容时不改变当前选择。
- 上传空状态必须提供始终可见的“选择照片”按钮，不能只依赖整块区域点击、拖放、悬停或粘贴；触屏设备通过系统文件选择器访问相册或可用的拍照来源。
- “选择照片 / 更换图片”使用原生 `label` 与文件输入关联，不依赖脚本模拟点击。
- 选择照片后必须显示完整预览和文件名，并提供“更换图片”和“移除”。
- 再次粘贴图片等同于更换；移除只清除待生成照片，不影响已生成人物形象。
- 上传后只做方向校正和安全缩放，不裁剪为头像。
- 原始照片只用于首张人物形象生成。
- 生成失败后服务端删除临时原图，浏览器仍保留当前所选文件，老师可直接再次提交。
- 首张人物形象成功保存后立即删除原始照片。
- 后续微调只使用人物形象，不再使用原始照片。
- 输出固定为 `1024×1536` 竖版单人全身图，从头到脚完整可见。

### 描述生成

上传照片是默认入口；描述生成是备选入口。界面不显示结果准确率提示，老师不填写底层 prompt。

照片模式使用“风格要求（可修改）”，默认内容为：

```text
二维绘本风格，单人全身，正面自然站立，背景简洁明亮；保留照片中的五官和辨识特征。
```

全身构图、手脚完整、单人、无文字水印等生成约束始终由系统 prompt 强制保证，不依赖老师保留默认文案。

描述生成使用一组可直接修改的推荐默认值，不以“不匹配”作为默认状态。所有外貌维度始终可见，并按“整体印象 / 外貌细节 / 穿搭”分组，避免使用折叠入口隐藏能力：

- 发型
- 气质
- 衣着
- 发色
- 脸型
- 身形轮廓
- 眼镜
- 服装主色
- 标志性特征

预置允许老师改为“暂不指定”，但默认展示推荐值。如果预置不能表达需要，老师可以在“额外要求”中补充。界面不做人物外貌指纹或相似度匹配。

描述模式的补充文本字段命名为“补充要求（选填）”。

生成区不显示“每次生成 1 张图片”等不改变决策的说明。

系统自动叠加人物年龄、性别和统一二维绘本风格，编译为最终 prompt。选项快照保存在本次生成记录中，不回写人物基础表。

### 多轮微调

- 用户先选中一个成功版本。
- 输入一句修改要求，例如“换成圆框眼镜”或“衣服改成蓝色”。
- 每条修改要求生成一个子版本，记录 `parentAssetId`。
- 微调失败不改变当前形象，也不创建失败版本；当前修改要求保留，便于再次提交。
- 用户可从任意历史版本继续生成新分支。
- 右侧以轻量对话式时间线展示当前选中版本的祖先链，只显示本分支的修改要求和生成结果，不混入其他分支。
- 修改输入固定在结果态底部，提交成功后清空本次输入并选中新版本。
- MVP 不生成长篇 AI 回复，不做多个会话房间或复杂版本对比。

## 内部归档与恢复

- 老师端不出现删除、停用、归档、启用中、已停用或恢复等后台概念和操作。
- 内部归档接口执行软删除，不提供人物物理删除。
- 删除后人物不出现在列表和新课程选择器中。
- 历史课程保留人物快照和已选形象引用。
- 删除不移除任何人物形象版本；恢复能力保留给内部管理。

## 搜索与最近使用

人物选择和人物档案页使用同一查询能力。

- 按角色过滤。
- 搜索中文名和英文名，忽略英文大小写。
- 默认先展示最近参与课程的人物。
- `recent` 定义为人物参与课程关联记录中的最新时间，不因编辑档案而改变。
- 搜索结果按匹配结果优先，再按最近使用时间和姓名排序。

## API 合同

### `GET /api/people`

Query：

```ts
type PeopleQuery = {
  role?: "teacher" | "student";
  query?: string;
  status?: "active" | "archived";
  sort?: "recent" | "name";
  cursor?: string;
  limit?: number;
};
```

响应包含人物资料、当前形象摘要和最近使用时间。

### `POST /api/people`

创建人物基础资料，不自动产生图片费用。

### `PATCH /api/people/:id`

更新基础资料。类型不可修改。

### `POST /api/people/:id/archive`

仅供内部管理软删除人物，不删除资料或图片；教师端不调用此接口。

### `POST /api/people/:id/restore`

恢复人物。

### `GET /api/people/:id/visuals`

读取当前形象、版本历史和生成状态。

### `POST /api/people/:id/visuals/from-photo`

上传照片并生成首张全身人物形象。请求使用 multipart form data。

请求必须携带 `Idempotency-Key`，相同人物和相同 key 只能创建一次付费生成记录。

### `POST /api/people/:id/visuals/from-description`

根据外貌选项和额外要求生成首张形象。

请求必须携带 `Idempotency-Key`。

### `POST /api/people/:id/visuals/:assetId/refine`

基于指定成功版本和一条修改要求生成子版本。

请求必须携带 `Idempotency-Key`。

### `POST /api/people/:id/visuals/:assetId/select`

把指定成功版本设为人物当前形象。

## 数据结构

人物档案使用当前 schema 中的正式领域表。

```ts
type Person = {
  id: string;
  role: "teacher" | "student";
  chineseName: string;
  englishName: string;
  age: number;
  gender: "male" | "female";
  notes: string | null;
  activeVisualAssetId: string | null;
  archivedAt: Date | null;
  createdAt: Date;
  updatedAt: Date;
};

type PersonVisualAsset = {
  id: string;
  personId: string;
  parentAssetId: string | null;
  sourceMode: "photo" | "description" | "revision";
  appearanceConfig: unknown | null;
  userInstruction: string | null;
  compiledPrompt: string;
  sourceHash: string;
  status: "pending" | "submitting" | "succeeded" | "failed";
  provider: string;
  providerImageUrl: string | null;
  storagePath: string | null;
  publicUrl: string | null;
  temporarySourcePath: string | null;
  failureReason: string | null;
  createdAt: Date;
  updatedAt: Date;
};
```

`Person.activeVisualAssetId` 是当前人物形象的唯一引用。历史版本是否为当前版本不再保存第二个布尔字段。

## 生成状态与失败恢复

- 生成请求先创建 `pending` 记录。
- 数据库用人物、操作类型和 `Idempotency-Key` 唯一约束防止重复创建付费记录。
- 提交付费请求前用条件更新抢占为 `submitting`，防止重复点击产生双倍费用。
- 生成或本地保存失败时删除本次人物形象资产，失败尝试不进入历史列表。
- 新版本成功不会自动选中。
- 选择当前形象失败时，原当前形象不变。
- 不引入 MQ、Worker 或 WebSocket。

## 验收标准

- 老师和学生都必须填写中文名、英文名、年龄和性别。
- 页面不再出现兴趣、学习目标和自由文本外貌字段。
- 页面不展示后台归档状态或解释性产品文案。
- 新增 / 编辑采用居中界面，基础信息与形象不再拆成两个入口。
- 教师端不展示删除、停用、归档或恢复操作。
- 支持照片生成和描述生成竖版全身人物形象，照片入口默认选中。
- 照片支持选择、拖放和剪贴板粘贴上传。
- 照片选中后显示预览、文件名、更换和移除操作。
- 照片模式提供带默认可理解文案的“风格要求”，描述模式提供“补充要求”。
- 描述生成默认给出可修改的推荐值，所有外貌维度直接可见，并可改为“暂不指定”。
- 额外要求用于补充预置未覆盖内容。
- 生成区不显示单次图片数量等冗余说明。
- 每次生成只产生一张图片。
- 支持基于任意成功版本继续微调。
- 首次创建与多轮修改互斥展示；成功后自动切换到多轮修改，只有点击“重新创建”才返回首次创建。
- 多轮修改只展示当前版本所在分支，失败尝试不保存、不展示历史缩略图。
- 历史版本可查看，只有显式选择才成为当前形象。
- 原始照片在首张人物形象成功后删除。
- 失败时保留当前输入，老师可直接再次提交；失败尝试不进入历史。
- 长时间生成时有独立等待态、实际等待时间和稳定说明；成功或失败后自动离开等待态。
- 人物只能软删除，不能物理删除；内部保留恢复能力。
- 核心操作满足键盘、焦点和状态可读性要求。
