# 课程 AI 工作台 UI 守则

本守则适用于课程创建流程中包含 AI 长任务、聊天时间线、结果预览和底部步骤操作的工作台。具体模块文档可以增加业务约束，但不得违反本守则。

## 布局责任边界

- 工作台根结构固定为“页面标题 / 可伸缩工作区 / 底部步骤操作”。底部步骤操作必须参与布局，不得通过 `fixed` 或覆盖内容的 `sticky` 悬浮在聊天框、结果框之上。
- 生成结果后的聊天栏与结果栏共用同一可用高度。两栏各自只让中间内容区滚动；聊天设置、聊天输入、结果导航和底部步骤操作保持可见。
- 不得同时叠加多组 `100dvh - 常数`、强制最小高度和悬浮底栏。视口不足时允许工作台自然变为页面滚动，但内容不得互相遮挡。
- 初始态不复用生成后的空双栏。初始主操作按内容自然高度展示，外沿与页面标题对齐，主要表单保持可读宽度，不用大面积空白制造“工作区感”。
- 响应式判断优先依据工作区实际可用宽度，不依据设备名称。窄宽度使用单面板切换；达到双栏最低宽度后才启用紧凑双栏；宽屏再增加结果栏比例。
- 同一业务状态在手机、iPad 和 PC 上只改变排布与信息密度，不改变功能、操作名称、数据或恢复策略。

## AI Loading 表达真实任务

- 用户界面不展示内部 Prompt 名、provider、模型调用轮次、原始校验错误或 JSON 修复细节；使用老师能理解的业务任务名称。
- Loading 卡的数据来源必须是持久化 operation 的任务类型、目标、阶段、开始时间和更新时间。不得依靠中文文案包含关系推断业务状态。
- 不显示虚假完成百分比、虚假剩余时间或随机轮播的“当前步骤”。只显示服务端已经进入的真实阶段、已等待时间和后续将执行的确定性步骤。
- 每类任务单独定义阶段说明。至少覆盖：需求理解、格式整理、参考资料、故事方向、故事大纲、故事修改、正文与课后阅读、练习、局部内容修改及自动修复。
- 非 AI 操作（保存设置、确认步骤、重新开始、页面跳转）使用短时系统状态，不伪装成 AI 生成。
- 同一时刻只展示一个当前运行任务。顶部摘要、聊天 Loading 和移动端状态标记可以同步同一份数据，但不得形成互相矛盾的状态判断。

## 长等待与恢复

- 0–30 秒展示当前任务和阶段；30–90 秒说明任务仍在处理且无需重复提交；90 秒后说明长内容可能仍在生成或校验，并允许老师稍后返回查看。
- “仍在运行”只能由持久 operation 的运行状态支持。页面暂时获取不到状态时显示“正在重新获取任务状态”，不得自行宣布 AI 失败。
- 真正失败、租约过期或结果未确认由服务端状态决定。失败时必须说明哪些旧成果仍被保留，并把重试动作放在失败信息旁边。
- 结果未确认后再次请求可能产生新的 AI 成本，必须由老师主动触发；页面不得自动重复提交。
- AI 请求发出后不提供伪取消。若当前架构无法撤回上游调用或停止计费，不得使用“取消生成”误导老师。

## 多端信息密度

- 窄屏 Loading 卡默认展示任务、当前阶段和计时，后续阶段与说明可以折叠；聊天 / 结果切换必须显示运行标记。
- 紧凑双栏保留完整任务名称和当前阶段，阶段列表改为纵向紧凑布局，不使用横向步骤条挤压文字。
- 宽屏可以展示完整阶段列表和行动建议，但 Loading 卡宽度仍遵循聊天消息阅读宽度，不横向铺满聊天栏。
- 会话态输入框默认只占一行，按真实输入内容向上增长，到达上限后才在输入框内部滚动；发送动作使用输入框内的轻量图标按钮，不另占操作行。初始态主操作仍可保留明确文字按钮。
- 已有对话历史后，不重复常驻展示已失去行动价值的初始引导消息。结果导航、翻页和当前页操作应合并到同一局部工具栏，优先把高度留给聊天记录和成果本身。
- 旧版本提醒保持单行紧凑表达，并允许老师在当前页面关闭；关闭只影响提示可见性，不得清除旧版本状态或解除业务限制。
- 聊天时间线和结果预览首次打开、切换面板或切换结果页时，默认定位到最新内容；若内容未溢出，保持自然起点，不制造无意义滚动。
- 横向 Tab 和工作区内部滚动保留滚轮、触控与键盘能力，但不展示 Windows 原生滚动条箭头。会因内容高度变化而增减滚动条的结果区必须使用稳定滚动模式，避免提示关闭、窗口缩放或内容重排时因滚动条宽度反馈产生抖动。
- 触控按钮和 Tab 保持至少 44px 可点击高度；横向内容不得要求精确拖动；所有焦点轮廓只属于真实可交互控件。

## 工程维护要求

- Step 2、Step 4 等同类工作台复用共享布局与共享 AI 任务状态组件；业务模块只提供任务定义和内容，不复制响应式高度规则。
- 新增 AI 操作时必须同时补齐任务名称、阶段映射、长等待说明、失败恢复文案和组件测试。
- 布局测试必须覆盖初始态、运行态、结果态和低高度窗口；状态测试必须覆盖刷新恢复、失败、结果未确认和局部目标恢复。
- UI 重构不得改变 API 请求次数、幂等键、AI Prompt、业务状态流转或成功成果覆盖规则，除非目标模块文档另行确认。
